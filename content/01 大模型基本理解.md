### 文本生成多样性

#### [Q1] 大模型是怎么让生成的文本丰富而不单调的？

从**训练**和**推理**两个角度来看：

**训练角度：**

1. **模型参数量巨大，学习到多样化的语言模式。** 基于 Transformer 的大模型参数量达到数十亿乃至数万亿，能够在预训练阶段从海量文本中学习到多样化的语言模式、文体风格和知识结构。参数量越大，模型能表达的条件概率分布越精细。

2. **各种微调技术使模型在垂直领域获得更强生成能力。** P-Tuning、LoRA 等参数高效微调方法以极低成本激活模型在特定领域的生成多样性，同时保留预训练阶段学到的广泛知识。

3. **训练阶段引入专门设计的损失函数。** 除标准的 next-token 预测 loss 外，还可以加入多样性相关的惩罚项（如 n-gram 重复惩罚）抑制模型生成单调内容，或通过 RLHF 中的奖励模型引导模型朝向人类偏好的多样化输出优化。

**推理角度：**

1. **温度参数（Temperature）。** 在 Softmax 前对 logit 除以温度 $\tau$，控制概率分布的"尖锐程度"：$\tau < 1$ 时分布更集中（更确定），$\tau > 1$ 时分布更平坦（更多样）。
2. **Nucleus Sampling（Top-p Sampling）。** 只从累积概率达到 $p$ 的最小词汇集合中采样，在保证质量的同时引入多样性。
3. **Top-k Sampling。** 只从概率最高的 $k$ 个词中采样。

#### [Q2] 推理时的文本生成策略有哪些？

| 策略 | 核心思路 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 贪心解码（Greedy） | 每步选概率最高的 token | 快速确定 | 容易陷入重复，多样性差 |
| 束搜索（Beam Search） | 维护 $k$ 条候选序列，选整体得分最高 | 质量较稳定 | 生成内容单调，常产生"安全"但无聊的文本 |
| 随机采样（Sampling） | 按概率分布随机抽取 | 多样性好 | 可能产生低质量或不连贯内容 |
| Top-k Sampling | 从概率最高的 $k$ 个词中采样 | 兼顾质量与多样性 | $k$ 固定，对概率分布形状不自适应 |
| Nucleus Sampling（Top-p） | 从累积概率达到 $p$ 的最小词集中采样 | 自适应截断，质量与多样性均衡 | $p$ 需要调整，极端分布下仍可能出问题 |
| Typical Sampling | 选择信息量接近条件熵期望值的 token | 在语言模型中更"自然" | 实现略复杂，使用较少 |
| Temperature Sampling | 对 logit 除以 $\tau$ 再采样 | 简单直接 | 单独使用时对极端低概率词没有硬截断 |

实际应用中通常**组合使用**：如 Temperature + Top-p，或 Temperature + Top-k。

#### [Q10] 一般 p 和 k 取多少？实际工程例子？

**Top-p（Nucleus Sampling）常用取值：**

- 通用范围：**0.85–0.95**
- 对话/问答：0.9（平衡多样性与质量）
- 事实问答 / RAG：0.7–0.85（偏保守，减少低质量候选）
- 创意写作：0.9–0.95（允许更宽的词集）

**Top-k 常用取值：**

- 通用范围：**40–100**
- 对话类：40–50
- 创意写作：50–100

**实际框架与系统默认参数：**

| 系统 / 框架 | 默认 top_p | 默认 top_k | 默认 temperature | 备注 |
| --- | --- | --- | --- | --- |
| OpenAI API（GPT-3.5/4） | 1.0 | 不支持 | 1.0 | 默认不截断，用户自行调整 |
| LLaMA 2 Chat（官方推荐） | 0.9 | — | 0.6 | Meta tech report 推荐参数 |
| Ollama 默认配置 | 0.9 | 40 | 0.8 | 本地部署最常见配置 |
| HuggingFace `generate()` | 1.0 | 50 | 1.0 | 默认只启用 top_k=50 |
| vLLM SamplingParams | 1.0 | -1（不截断） | 1.0 | 生产部署默认全量 |
| Qwen2.5 官方推荐 | 0.9 | — | 0.7 | 官方 README 推荐配置 |

**工程建议：**
- 不建议同时开启 Top-k 和 Top-p，两者截断逻辑会相互干扰
- 实践中常用组合：**Temperature（0.7–0.9）+ Top-p（0.9）**，不开 Top-k
- RAG / 事实性任务：temperature=0.3–0.6，top_p=0.8–0.9
- 代码生成场景：temperature=0.2–0.4，top_p=0.95

> [!tip] 为什么工程中更常用 Top-p 而不是 Top-k？
> 核心原因是 **Top-k 的候选集大小对分布形状不自适应**，而语言模型每一步的概率分布形状差异极大：
>
> - **Top-k 的问题：** $k$ 是固定常数。分布尖锐时（模型很确定），前 3 个词就覆盖了 99% 的概率，但 Top-k=50 仍强制采样 50 个词，引入大量噪声；分布平坦时（模型不确定），50 个词可能只覆盖 20% 的概率，大量合理候选被截断。
> - **Top-p 的优势：** 候选集大小随当前步骤的分布自动调整——==模型确信时核很小（接近贪心），模型不确定时核自动扩大（保留多样性）==。这使 Top-p 能够在不同生成步骤之间自动切换策略，无需手动调整。
>
> 此外，$k$ 的最优值高度依赖词表大小和具体模型，难以在不同模型间通用；而 $p \in (0, 1)$ 的语义固定（"累积到多少概率就截断"），更易于跨模型迁移和直觉调参。
>
> 因此大多数生产系统（OpenAI API、vLLM、Ollama 等）默认只暴露 `top_p`，或将 `top_k` 设为 -1（关闭），以 Temperature + Top-p 作为主要采样组合。


> [!note] 不同任务为什么选不同参数？
> 本质是：**不同任务对"正确性"和"多样性"的权衡不同**。
>
> **通用对话（temperature=0.7–0.9，top_p=0.9）**
> 对话没有唯一正确答案，语言需要自然流畅、略有变化。较高温度使输出更接近人类语言的随机性，top_p=0.9 保留了足够的候选词空间。
>
> **RAG / 事实性任务（temperature=0.3–0.6，top_p=0.8–0.9）**
> 答案必须基于检索到的文档，不能"发挥"。低温度压缩分布，让模型更多选择高概率（更确定）的词，降低幻觉风险；top_p 也略收紧（0.8–0.9），进一步排除低概率的不稳定候选词。
>
> ⭐️ **代码生成（temperature=0.2–0.4，top_p=0.95）**
> 代码语法严格，一个错误 token 可能导致整段代码无法运行，因此温度要很低以保证确定性。但 top_p 反而设得**更高**（0.95），原因是：
> - 代码中存在大量必要的"小概率词"——变量名、库函数、特定语法关键字，它们在通用语言模型里概率偏低，但在当前上下文里是唯一正确选项
> - 温度已经很低，概率分布已经非常尖锐，此时 top_p=0.95 实际上仍只保留极少数词，不会引入随机性；但如果把 top_p 也压低到 0.8，可能误杀这些"罕见但必要"的代码 token
> - **低温度负责"稳"，高 top_p 负责"不误杀合法 token"**，两者分工不同

#### [Q3] Temperature 参数如何影响生成？

![[Pasted image 20260622205102.png|500]]

设模型在某一步的 logit 向量为 $\mathbf{l} = [l_1, l_2, \ldots, l_V]$，引入温度 $\tau$ 后的概率分布为：

$$
P(w_i) = \frac{\exp(l_i / \tau)}{\sum_{j=1}^{V} \exp(l_j / \tau)}
$$

| $\tau$ 取值 | 效果 |
| --- | --- |
| $\tau \to 0$（极小） | 趋近于贪心解码，始终选概率最高的 token，完全确定性 |
| $\tau = 1$ | 使用模型原始概率分布 |
| $\tau > 1$ | 概率分布更平坦，低概率词被"提升"，输出更随机多样 |
| $\tau \to \infty$ | 趋近于均匀分布，完全随机采样 |

> [!tip] Temperature 的实际调优建议
> - 对话/问答类任务：$\tau \approx 0.7$–$0.9$，保持流畅的同时增加自然度。
> - 创意写作：$\tau \approx 1.0$–$1.2$，允许更多意外词汇出现。
> - 代码生成/事实问答：$\tau \approx 0.2$–$0.5$，偏向确定性输出。
> - Temperature 通常与 Top-p 或 Top-k 联合使用，先用 Temperature 调整分布，再用 Top-p/k 截断尾部低概率词。

#### [Q9] Nucleus Sampling 和 Top-k 直观看都是"从高概率词里采样"，有什么本质区别？

关键区别在于**候选集的大小是否自适应**：

- **Top-k**：每次固定从概率最高的 $k$ 个词中采样，$k$ 是常数。
- **Top-p（Nucleus）**：每次动态选出累积概率恰好超过 $p$ 的**最小词集**，候选集大小随分布形状变化。

具体来说，假设 $p = 0.9$、$k = 50$：

| 当前分布形状 | Top-k=50 的行为 | Top-p=0.9 的行为 |
| --- | --- | --- |
| **尖锐**（"the" 概率 0.92） | 仍从 50 个词采样，引入不必要随机性 | 只 1–2 个词就超过 0.9，接近贪心 |
| **平坦**（每词概率均约 0.5%） | 只从 50 个词中采样，错过大量合理选项 | 可能需要 200+ 个词才能累积到 0.9，充分保留多样性 |

**直觉：** Top-p 的"核"（Nucleus）大小是模型当前**置信度**的函数——模型越确定，核越小；模型越不确定，核越大。Top-k 无论模型置信与否，候选集始终是固定的 $k$ 个。这就是为什么 Top-p 在实践中通常优于 Top-k 作为单独策略使用：它能在"该保守时保守，该多样时多样"之间自动切换。

#### [Q11] 按概率分布随机抽取是什么概率分布？如何保证随机到的 token 的质量？

**是什么概率分布？**

模型在每一步生成时输出 logit 向量 $\mathbf{l} \in \mathbb{R}^V$（$V$ 为词表大小），经过 Temperature Scaling 和 Softmax 后得到：

$$P(w_i) = \frac{\exp(l_i / \tau)}{\sum_{j=1}^V \exp(l_j / \tau)}$$

这是定义在整个词表上的**离散概率分布（Categorical Distribution）**。"按概率分布随机抽取"即**多项式采样（Multinomial Sampling）**：每个 token $w_i$ 被选中的概率恰好等于 $P(w_i)$。

**与贪心解码的区别：**

| 策略 | 公式 | 行为 |
| --- | --- | --- |
| 贪心 | $w_t = \arg\max_i P(w_i)$ | 始终选概率最高的词，完全确定性 |
| 随机采样 | $w_t \sim \text{Categorical}(P)$ | 概率高的词**更可能**被选中，但非必然 |

**如何保证随机到的 token 的质量？**

原始概率分布会给低质量词（极低概率词）分配非零概率，以下机制共同保证质量：

1. **Temperature 缩放**（$\tau < 1$）：压缩分布，放大高概率词的相对优势，低概率词被进一步压低
2. **Top-k 截断**：只保留概率最高的 $k$ 个词，将其余词概率置 0 后重新归一化
3. **Top-p 截断**：保留累积概率达到 $p$ 的最小词集，动态排除低质量长尾
4. **Repetition Penalty**：降低已生成 token 的 logit，防止重复采样

这些机制按顺序叠加：Temperature → Top-k/Top-p 截断 → 重新归一化 → 采样。最终采样的 token 来自经过多层过滤后的"高质量子分布"，而非原始的全词表分布。

#### [Q16] 什么是多项式采样（Multinomial Sampling）？

多项式采样是语言模型生成时最基础的随机采样方式：**每个 token 被选中的概率恰好等于模型输出的归一化概率 $P(w_i)$**。

**形式化定义：**

设当前步骤的词表概率分布为：

$$\mathbf{P} = [P(w_1), P(w_2), \ldots, P(w_V)], \quad \sum_{i=1}^V P(w_i) = 1$$

多项式采样即从这个 Categorical 分布中抽取一个样本：

$$w_t \sim \text{Categorical}(\mathbf{P})$$

**实现方式（逆 CDF 采样）：**

实际代码中通常使用逆累积分布函数（Inverse CDF）：

1. 计算累积概率：$F(w_i) = \sum_{j \leq i} P(w_j)$
2. 生成均匀随机数 $u \sim \text{Uniform}(0, 1)$
3. 选择第一个满足 $F(w_i) \geq u$ 的 token $w_i$

在 PyTorch 中即 `torch.multinomial(probs, num_samples=1)`。

**与贪心解码的对比：**

| 策略 | 公式 | 行为 |
| --- | --- | --- |
| 贪心解码 | $w_t = \arg\max_i P(w_i)$ | 始终选最高概率词，完全确定性 |
| 多项式采样 | $w_t \sim \text{Categorical}(\mathbf{P})$ | 概率高的词更可能被选中，但非必然 |

**为什么不直接用原始多项式采样？**

原始多项式采样对全词表分布采样，存在问题：极低概率词（质量差、语义不连贯）仍有非零概率被选中，导致生成文本偶尔"突然跳到随机词"。

==这就是为什么实践中先用 Temperature 缩放、再用 Top-k 或 Top-p 截断，最后才进行多项式采样——**Top-k / Top-p 是多项式采样的前处理**，保证采样只在"高质量子分布"上进行：==

$$\text{Logits} \xrightarrow{\text{Temperature}} \xrightarrow{\text{Top-k/Top-p 截断}} \xrightarrow{\text{归一化}} \xrightarrow{\text{多项式采样}} w_t$$


> [!important] 名称辨析
> "随机采样"、"Ancestral Sampling"、"Multinomial Sampling" 在语言模型语境中通常指同一件事——从当前步骤的（经过处理的）概率分布中按概率抽取一个 token。贪心解码和 Beam Search 是**不采样**的确定性方法；Temperature / Top-k / Top-p 是**采样前的分布调整**，最终的抽样动作本身均是多项式采样。

### 复读机问题

#### [Q4] 什么是 LLMs 的"复读机"问题？

LLMs 的复读机问题（Repetition Problem）指模型在生成过程中出现不同粒度的重复现象，分为以下几类：

1. **字符/词级别重复。** 模型对一个词或字符不断重复生成。  
   例：`"steckdose steckdose steckdose steckdose ..."`  
   常见于长文本生成末尾或领域外输入场景。

2. **句子级别重复。** 模型对一句话反复生成，陷入循环。  
   例：多模态模型图片描述中不断重复 `"这是一个杯子，这是一个杯子..."`

3. **段落/章节级别重复。** 对于多次相同或相似的 prompt，模型输出几乎完全一致，没有创新性。  
   例：让模型写关于春天的小作文，结果千篇一律，几乎一模一样。

4. **信息单一，有效信息量低。** 对不同 prompt，模型生成内容高度相似，信息量少，内容偏斜（信息熵偏低）。  
   例：无论用户问什么，回答都绕回几个固定的模板句式。

---

#### [Q5] 复读机问题的成因是什么？

**1. 数据偏差（Data Bias）**

大型语言模型通过预训练阶段在大规模无标签数据上训练。若训练数据中存在大量重复文本，或某些特定句子/短语出现频率过高，模型在生成时会倾向于复制这些常见模式。

> **实际例子：**
> - **LLaMA / LLaMA 2（Meta）** 的预训练语料来自 CommonCrawl、C4 等网页爬取数据，其中存在大量模板化文章、SEO 堆砌段落。模型在这类输入上生成时容易滑向重复短语。
> - **早期中文 LLM**（如百川、MOSS 早期版本）的中文预训练数据质量参差不齐，部分来自电商、论坛等重复度高的来源，导致在中文生成中容易出现"废话文学"式重复。
> - **专业翻译模型（M2M-100、NLLB）** 的训练数据中，电商标题类数据天然含有大量词序堆叠和关键词重复（如"纯棉 纯棉 纯棉 男款 T恤"），导致模型在此类输入上重复概率比 flores-101 通用文本高 20 倍以上。

---

**2. 训练目标的限制（Teacher Forcing / Exposure Bias）**

自监督学习中，模型通过预测下一个 token 来训练（next-token prediction）。训练时每步输入均为真实的 ground-truth token（Teacher Forcing），但推理时输入的是模型自己的上一步预测结果。一旦生成了偏差 token，后续 token 的条件分布是训练时从未见过的，模型容易滑入重复局部最优。

> **实际例子：**
> - 这是**所有自回归 LLM 的共性问题**，包括 GPT 系列、LLaMA 系列、Qwen 系列、ChatGLM 等。
> - **GPT-2** 在使用贪心解码时，尤其在输入为低频或领域外文本时，极易陷入句子级重复循环。OpenAI 在 GPT-2 的 demo 中特别提醒"使用 Top-p 采样而非贪心解码"。
> - **BART / T5** 的 Decoder 部分同样使用 Teacher Forcing 训练，在生成长摘要时重复段落的问题已被论文记录（"the model repeats itself"）。

---

**3. 缺乏多样性的训练数据（Lack of Diverse Training Data）**

训练数据在语言表达和语境上缺乏多样性，模型无法学到足够多样的生成模式，导致复读机问题。

> **实际例子：**
> - **垂直领域小模型**（如早期医疗 / 法律 LLM）往往只在特定领域语料上训练，词汇分布极窄，模型在生成时极易重复领域内的高频术语和模板句式（如"根据上述分析……根据上述分析……"）。
> - **代码生成模型（早期 Codex）** 在特定编程题类型上，因训练样本中大量解法高度相似，模型生成的代码注释和变量命名几乎一模一样，表现出明显的段落级重复。
> - **多模态模型（如早期 LLaVA 1.0）** 的视觉描述训练数据（如 COCO Captions）句式集中，模型在生成图片描述时容易反复输出 "A man is… A man is…" 这类句式。

---

**4. 模型结构与 Induction Head 机制**

Transformer 模型中存在一类被称为 **Induction Head** 的注意力头（Olsson et al., 2022）：它们实现了一种简单的"复制规则"——**当前上下文中出现了 token A 后紧跟 token B，那么下次遇到 A 时，模型倾向于再次预测 B**。

这一机制是所有 Transformer 中普遍存在的回路（circuit），本质上是模型的"上下文复制"能力，是 In-Context Learning 的基础——但也是复读机问题的结构性根源。

$$
\text{Induction Head:} \quad [A, B, \ldots, A] \to B
$$

**在翻译场景中的特殊表现**：

由于 input 和 output 之间存在天然的语义差异（尤其是源语言和目标语言词序、结构不同），模型对低频或结构特殊的输入的条件概率分布更不确定。**输入句式越不常见（困惑度 perplexity 越高），翻译结果出现重复的可能性越高。**

> **实际例子：**
> - **M2M-100、NLLB（Meta）、ChatGPT、LLaMA** 在翻译电商标题（如"冬季保暖男款加绒加厚外套 2024 新款"）时，与翻译 flores-101 通用句子相比，复读机发生率高出数十倍，这正是因为电商标题 perplexity 极高、结构不规则，Induction Head 退化为简单复制。
> - **Mechanistic Interpretability 研究**（Anthropic, Olsson et al.）在 GPT-2 small 中直接识别出了 Induction Head 电路，证明所有规模的 Transformer 都存在此机制。

> [!note] Induction Head 的双面性
> Induction Head 是 In-Context Learning（ICL）能力的重要来源：模型看到示例 `[Q1→A1, Q2→A2, Q3→?]` 时，能够正确复制"给 Q 配 A"的模式。但在生成任务中，当模型不确定下一步应生成什么时，Induction Head 会退化为简单地从上文中复制最近出现的 token，造成重复。

---

**5. 信息熵视角：高熵输入导致模型"不知道说什么"**

从信息论角度看，模型在生成采样时，理论上应该**只采样那些与条件熵对应概率接近的字符**（Typical Sampling 的理论基础）。但对于信息熵非常高的输入（如电商标题：句子连贯性很弱、基本是关键词堆叠），模型的条件概率后验分布趋于平坦（Softmax 分布平滑），即**模型无法确定下一个词应该是什么**，因此更倾向于从上文已出现的词中挑选。

$$
H(X \mid \text{context}) \uparrow \implies P(\text{next token}) \text{ 趋于均匀} \implies \text{模型倾向复制上文}
$$

**为什么会一直重复同一个词 L？**  
当模型陷入重复循环后，前 $t-1$ 步的 token 分布趋于稳定。$t+1$ 步后，词 L 对应的概率质量在嵌入空间中沿前 $t-1$ 步 token 的 TSNE 二维分布均匀铺开，这正是**各向同性（Isotropy）** 问题——词向量分布趋于均匀球形，使得模型在生成时越来越难以区分不同 token，不断强化重复循环。

$$
\underbrace{\langle H, I, J, K, L \rangle}_{\text{已生成序列}} \xrightarrow{\text{各向同性}} P(L \mid H,I,J,K,L) \approx P(L \mid H,I,J,K,L,L,L)
$$

即添加更多重复的 L 后，下一步的分布几乎不发生变化，陷入稳定的重复不动点。

> **实际例子：**
> - **电商翻译场景**：flores-101 通用文本 vs. 电商标题文本，后者出现复读机的概率是前者的 **20 倍以上**（有实验记录）。
> - **M2M、NLLB、ChatGPT、LLaMA** 在电商标题翻译上的 TSNE 可视化均显示 `<H,I,J,K,L>, <H,I,J,K,L,L>, <H,I,J,K,L,L,L>` 的二维分布基本一致，说明重复 token 几乎不影响上下文语义表示——这是各向同性导致复读机的直接证据。
> - **多模态模型（LLaVA、早期 mPLUG-Owl）** 在图文对的文本侧信息熵高时（如专业图表描述），输出重复句子的频率显著高于普通图片问答任务。

#### [Q6] 如何解决 LLMs 的复读机问题？

**推理阶段（无需重新训练）：**

1. **Repetition Penalty（重复惩罚）。**  
   对已生成的 token，在 logit 阶段施加惩罚，降低其再次被选中的概率：
   $$
   l_i' = \begin{cases} l_i / \theta & \text{if } w_i \in \text{generated tokens},\; l_i > 0 \\ l_i \times \theta & \text{if } w_i \in \text{generated tokens},\; l_i < 0 \end{cases}
   $$
   其中 $\theta > 1$ 为惩罚系数（如 1.1–1.3）。HuggingFace `generate()` 中的 `repetition_penalty` 参数即此机制。

2. **N-gram 重复阻止（No Repeat N-gram）。**  
   在生成时记录已出现的 n-gram；若继续生成会形成已出现的 n-gram，则将对应 token 的概率置为 0。`no_repeat_ngram_size` 参数控制 n 的大小（常用 3–4）。

3. **调高 Temperature 或使用 Nucleus Sampling。**  
   增加随机性，避免贪心/低温模式下的局部最优陷阱。

4. **Diverse Beam Search。**  
   在标准 Beam Search 基础上，对同一 Group 内不同候选序列施加差异性惩罚，鼓励 Beam 之间产生不同的词汇选择（`num_beams=4, num_beam_groups=2`）。需注意，Beam Search 本质上仍在最大化概率框架内工作，==并不能从根本上降低重复概率==，在翻译测试中甚至可能增大重复率，但它确实改变了 Softmax 后的分布，在部分任务上能抑制重复生成。

5. **Contrastive Search（对比搜索）。**  
   同时从**训练**（对比 Loss）和**推理**（对比搜索）两个层面，解决因词向量各向同性（Isotropy）导致的重复退化问题。

   **训练阶段 — Contrastive Loss：** 对 token 表示施加对比约束，拉大不同 token 在表示空间的距离：

   $$\mathcal L_{CL}=\frac{1}{|x|\times(|x|-1)}\sum_{i=1}^{|x|}\sum_{j=1,\,j\neq i}^{|x|}\max\!\left\{0,\;\rho-s(h_{x_i},h_{x_i})+s(h_{x_i},h_{x_j})\right\}$$

   其中 $s(h_{x_i},h_{x_j})=\dfrac{h_{x_i}^\top h_{x_j}}{\|h_{x_i}\|\cdot\|h_{x_j}\|}$ 为余弦相似度，$\rho$ 为 margin。训练完成后，==不同 token 的表示在高维空间中彼此分离，模型就不再倾向于只生成个别重复词或字==。

   **推理阶段 — Contrastive Search：** 解码时对候选 token 同时考虑模型置信度和退化惩罚：

   $$x_t=\arg\max_{v\in V^{(k)}}\!\left\{(1-\alpha)\times\underbrace{p_\theta(v\mid x_{<t})}_{\text{model confidence}}-\alpha\times\underbrace{\max\!\left\{s(h_v,h_{x_j}):1\leq j\leq t-1\right\}}_{\text{degeneration penalty}}\right\}$$

   当候选 token $v$ 与历史已生成 token 的表示**高度相似**时，其概率受到惩罚；$\alpha\in(0,1)$ 控制惩罚强度，从 Top-$k$ 候选中选取得分最高的 token。

   ==与 Repetition Penalty 的本质区别==：前者在 **token ID 层面**惩罚已出现的词；Contrastive Search 在**表示空间**惩罚语义相似的候选，能区分"合法的同词复现"与"语义退化重复"。

   > 论文：*A Contrastive Framework for Neural Text Generation*（SimCTG）。HuggingFace 中，`model.generate()` 设置 `penalty_alpha=alpha`（$0<\alpha<1$）即可开启，**无需重新训练**。

   > [!note]
   > 对比 Loss 训练从**根因**解决各向同性问题；对比搜索可**单独使用**（只在解码阶段添加退化惩罚）。但两者均只能解决词/句级别重复，**无法解决多次输入相同 prompt 导致的输出单调性问题**。

**训练阶段：**

6. **在训练 loss 中加入 n-gram 重复惩罚项。**  
   对生成序列中出现的重复 n-gram 施加额外损失，让模型在训练时就学会规避重复。

7. **RLHF / DPO 引导。**  
   在偏好数据中将重复性输出标注为"差"、多样性输出标注为"好"，通过 RLHF 或 DPO 让模型直接优化多样性偏好。

8. **数据清洗，减少预训练数据中的重复内容。**  
   使用 MinHash、Deduplication 等方法对预训练语料去重，降低模型从数据中学到"重复是合理模式"的可能性。

**各方法对比总览：**

| 方法 | 阶段 | 解决的重复类型 | 核心局限 | HuggingFace 参数 |
| --- | --- | --- | --- | --- |
| Repetition Penalty | 推理 | token ID 层面词/短语重复 | 过强则破坏流畅性 | `repetition_penalty=1.1` |
| No Repeat N-gram | 推理 | n-gram 级硬阻断 | 可能误杀合法重复（如代码） | `no_repeat_ngram_size=3` |
| Temperature + Top-p | 推理 | 贪心/低温下的分布集中 | 不能解决 prompt 间单调性 | `temperature=0.8, top_p=0.9` |
| Diverse Beam Search | 推理 | 多 Beam 之间的相似性 | 不从根本上降低重复概率 | `num_beams=4, num_beam_groups=2` |
| Contrastive Search | 推理（+训练可选） | 表示空间语义相似退化 | 不能解决 prompt 间单调性 | `penalty_alpha=0.6` |
| 对比 Loss 训练 | 训练 | 各向同性根因 | 需重新训练 | — |
| n-gram Loss 惩罚 | 训练 | 训练时抑制重复模式 | 效果依赖数据分布 | — |
| RLHF / DPO | 训练 | 多样性输出偏好 | 成本高 | — |
| 数据清洗去重 | 预训练 | 从源头减少重复 | 无法用于已训练模型 | — |

> [!warning] 过度惩罚重复的风险
> Repetition Penalty 或 No-Repeat N-gram 过强时，模型可能被迫选择低概率、语义不连贯的词来规避重复，反而产生语义跳跃或语法错误。需要在多样性和流畅性之间调整参数，通常建议先用较小惩罚（如 `repetition_penalty=1.1`）观察效果。

#### [Q17] 什么是 Beam Search？

![[Pasted image 20260622204939.png|600]]

Beam Search 是贪心搜索的改进版本：**每个时间步不再只保留概率最高的 1 条路径，而是保留得分最高的 `num_beams` 条候选序列**，最终输出整体对数概率最高的序列。

**核心流程：**

1. **初始化：** 将起始 token 展开，保留 `num_beams` 个得分最高的候选；
2. **逐步扩展：** 对每条 Beam 展开所有可能的下一 token，共产生 `num_beams × |V|` 条候选路径；
3. **剪枝保留：** 按累积对数概率选出最高的 `num_beams` 条，继续扩展；
4. **终止输出：** 所有 Beam 遇到 EOS 或达到最大长度时停止，取概率最高的序列输出。

最终得分通常加入**长度归一化**，防止短序列偏置：

$$\text{score}(y_{1:T})=\frac{1}{T^\alpha}\sum_{t=1}^{T}\log p_\theta(y_t\mid y_{<t})$$

其中 $\alpha\in[0,1]$ 为长度惩罚因子（常用 0.6–0.7）。**当 `num_beams=1` 时退化为贪心搜索。**

**与贪心、随机采样的对比：**

| 策略 | 核心思路 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 贪心（Greedy） | 每步选概率最高的 1 个 token | 速度最快 | 容易陷入局部最优，重复率高 |
| Beam Search | 每步保留 `num_beams` 条路径，选整体最优 | 比贪心找到更高概率序列，质量更稳定 | 输出单调"安全"，重复率仍高，计算量为贪心的 `num_beams` 倍 |
| 随机采样（Top-p） | 从概率分布中采样 | 多样性好 | 可能产生不连贯内容 |

> [!important]
> Beam Search 仍在**最大化概率**的框架内工作。==它并不能从根本上降低重复概率，甚至在机器翻译等任务中可能增大重复率==——因为高概率序列往往就是最"安全"的重复模式。真正缓解重复，需结合 Repetition Penalty、Diverse Beam Search 或 Contrastive Search。

HuggingFace 中，`model.generate()` 设置 `num_beams=2`（或更大值）即可开启；`num_beams=1` 等同关闭。

#### [Q7] Top-k 和 Top-p（Nucleus Sampling）各有什么局限？

**Top-k 的局限：**

$k$ 是固定值，不能自适应概率分布的形状：
- 若当前概率分布很**尖锐**（模型非常确定），前 3 个词几乎包含了全部概率质量，但 Top-k=50 仍会强制从 50 个词中采样，引入不必要的随机性；
- 若当前概率分布很**平坦**（模型不确定），前 50 个词可能只覆盖不到 30% 的概率，截断后损失了大量合理候选。

**Top-p 的局限：**

Top-p 能自适应分布形状，但：
- 当概率分布极度集中（如最高概率词超过 $p$），候选集只剩 1 个词，退化为贪心；
- 当概率分布极度分散时，Top-p 可能保留大量低质量词；
- $p$ 本身仍是需要调优的超参。

> [!note] 实践中的常用组合
> `temperature=0.8, top_p=0.9` 是较为常见的默认配置：先用 Temperature 压缩极端低概率词，再用 Top-p 限制候选词集上界。不建议同时开启 Top-k 和 Top-p，因为二者会相互干扰截断逻辑。

#### [Q8] 大模型生成中"幻觉"和"复读机"有什么区别？

| 问题 | 核心表现 | 根本原因 |
| --- | --- | --- |
| 复读机（Repetition） | 生成内容在形式上重复，同样的词/句/段反复出现 | 解码策略局部最优、曝光偏差、训练数据重复 |
| 幻觉（Hallucination） | 生成内容在语法上流畅，但事实上不正确或凭空捏造 | 模型参数化记忆不精确、训练目标不约束事实正确性 |

两者可以同时出现，也可以独立出现。复读机是**形式问题**（结构重复），幻觉是**内容问题**（事实错误）。解决方法也不同：复读机主要通过解码策略和 loss 设计缓解，幻觉需要知识增强（RAG）、校准（Calibration）或 RLHF 等手段。

#### [Q15] n-gram 重复惩罚公式？怎么做的？使用场景？

n-gram 重复惩罚有**训练阶段**和**推理阶段**两种形式：

**推理阶段（Hard Blocking）：**

维护已生成序列中所有 $n$-gram 的集合 $\mathcal{G}$。在每一步生成时，若当前的 $(n-1)$ 个历史 token 已经是某个 $n$-gram 的前缀，则将该 $n$-gram 最后一个词的概率强制置为 0：

$$p(w_t \mid y_{<t}) = 0, \quad \text{if } \langle y_{t-n+1}, \ldots, y_{t-1}, w_t \rangle \in \mathcal{G}$$

实现即 HuggingFace `generate()` 的 `no_repeat_ngram_size=n` 参数（常用 $n=3$ 或 $4$）。

**训练阶段（Soft Penalty）：**

对生成序列中已出现的 $n$-gram，在 log-prob 上施加惩罚：对 token $w_t$，若其与前 $n-1$ 个 token 构成已见 $n$-gram，则在 loss 中加入额外惩罚项：

$$\mathcal{L}_{\text{rep}} = \mathcal{L}_{\text{ce}} + \alpha \sum_t \mathbf{1}[\langle y_{t-n+1},\ldots,y_t\rangle \in \mathcal{G}_{<t}] \cdot (-\log p(y_t \mid y_{<t}))$$

即对"形成重复 $n$-gram 的那步预测"施加额外的交叉熵放大。

**Coverage Loss（See et al., "Get to the Point", 2017）：** 摘要生成中另一种常用形式，通过积累历史注意力分布 $c_t = \sum_{t'<t} a_{t'}$ 惩罚模型重复关注相同的源文本位置：
$$\mathcal{L}_{\text{cov}} = \sum_t \sum_i \min(a_t^i,\, c_t^i)$$

**使用场景：**

| 场景 | 推荐方式 |
| --- | --- |
| 摘要生成（重复源文本段落） | Coverage Loss（训练）+ `no_repeat_ngram_size`（推理） |
| 对话/长文本生成（句子循环重复） | `repetition_penalty` + `no_repeat_ngram_size` |
| 机器翻译（词/短语重复） | `repetition_penalty`（训练 Soft Penalty 效果更持久） |
| 代码生成（重复代码块） | 较小 `no_repeat_ngram_size`（$n=5$–$6$），避免误杀合法重复 |
