### LLM 训练 Pipeline

#### [Q1] LLM 的经典训练 Pipeline 是什么？

经典 Decoder-only LLM 通常经历以下阶段：

1. **Pre-training（预训练）**  
   在海量通用语料上进行自监督 next-token prediction，学习语言规律、知识和基础能力，得到 **Base Model** 。

2. **Mid-training / Continued Pre-training（可选）**  
   使用数学、代码、专业领域、长上下文等针对性语料继续预训练，补充知识或增强专项能力。

3. **Supervised Fine-tuning（SFT）**  
   使用指令—回答数据训练模型理解指令、遵循格式并完成任务，得到初步的 **Instruct Model** 。

4. **Preference Alignment / Reinforcement Learning**  
   使用人类或 AI 偏好进一步优化帮助性、安全性和回答质量。典型方法包括 RLHF、RLAIF、DPO、PPO 等。

5. **Evaluation & Deployment**  
   进行能力、安全、偏差和鲁棒性评测，再执行量化、蒸馏、推理优化与上线监控。

$$
\text{Raw Data}
\rightarrow
\text{Pre-training}
\rightarrow
\text{Base Model}
\rightarrow
\text{SFT}
\rightarrow
\text{Preference/RL Training}
\rightarrow
\text{Chat Model}
$$

> [!important] Pipeline 并非固定不变
> 现代训练流程可能反复交替执行数据生成、SFT、偏好优化和评测；也不是所有模型都必须使用 RLHF。高质量 SFT、DPO 或可验证奖励训练都可能成为主要后训练方案。

---

#### [Q2] Base Model、Instruct Model 和 Chat Model 有什么区别？

| 模型类型 | 主要训练阶段 | 典型行为 |
| --- | --- | --- |
| Base Model | 预训练 | 擅长续写文本，但不一定稳定遵循指令 |
| Instruct Model | Base Model + SFT | 能理解并完成单轮指令 |
| Chat Model | SFT + 偏好/安全/多轮对话训练 | 更适合对话，强调帮助性、安全性和交互体验 |

这些名称不是严格统一的标准。实践中，Instruct Model 与 Chat Model 经常混用。

==Base Model 学会“语言和知识”，SFT 教会它“如何响应指令”，偏好对齐进一步塑造“什么样的回答更合适”。==

### 预训练基础

#### [Q3] 什么是 LLM 预训练？

预训练（Pre-training）通常是指从随机初始化开始，在海量无人工任务标签的文本、代码等数据上进行自监督学习。

Decoder-only LLM 最常见的目标是：根据前文预测下一个 token。

$$
\mathcal{L}_{\mathrm{NTP}}
=
-\sum_{t=1}^{T}
\log p_\theta(x_t\mid x_{<t})
$$

预训练完成后得到 Base Model。它通常已经具备语言建模、知识记忆、上下文学习和一定的推理能力，但不一定能可靠地遵循用户指令。

关于公式中的负对数，参见：[[损失函数#Q12 负对数似然（NLL）会用在哪里？为什么要取负对数？]]

> [!note] “无标注”不等于“没有监督信号”
> 原始语料不需要人工逐条标注，但每个位置的真实下一个 token 都能自动构成训练标签，因此更准确的说法是**自监督学习** 。

---

#### [Q4] 为什么预测下一个 token 能让模型学到知识和能力？

准确预测下一个 token，不仅需要学习词频，还需要压缩和利用文本中的多层结构：

- 语法和语义关系；
- 实体、事实与世界知识；
- 文体、对话和任务格式；
- 代码执行与数学推导模式；
- 长距离依赖和上下文规律。

从概率建模角度，模型学习的是：

$$
p_\theta(x_1,\ldots,x_T)
=
\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t})
$$

如果模型能准确建模大规模文本分布，就必须形成能够预测这些数据的内部表示。

> [!tip] 更深刻的理解
> Next-token prediction 的优势不是目标本身“神奇”，而是它同时具备**监督信号密集、数据易扩展、训练目标统一** 三个特点。能力最终来自目标、数据、模型规模和优化过程的共同作用。

---

#### [Q5] 预训练为什么通常使用 Causal Language Modeling？

Decoder-only LLM 使用因果掩码，使位置 $t$ 只能关注 $x_{\le t}$，然后预测 $x_{t+1}$。

主要原因是：

1. **训练与生成一致**：推理时也是根据已有前缀逐 token 生成；
2. **目标统一**：问答、翻译、代码和对话都可以表示为条件文本生成；
3. **数据利用率高**：序列中几乎每个 token 都能提供监督信号；
4. **扩展性好**：容易在海量异构语料和大规模分布式系统上训练。

其局限是只能利用左侧上下文预测当前 token；对于纯文本理解任务，双向编码器有时更高效。

### 预训练数据与训练过程

#### [Q6] LLM 的预训练数据通常包括哪些类型？

常见数据来源包括：

- 网页、百科、书籍、新闻和论坛；
- 学术论文与技术文档；
- GitHub 等代码语料；
- 数学、问答和结构化数据；
- 多语言语料；
- 经过筛选的合成数据。

数据处理通常包含：

1. 文档解析与正文提取；
2. 语言识别和质量过滤；
3. URL、文档及近重复去重；
4. 隐私、恶意内容和许可证过滤；
5. 数据分类与混合配比；
6. Tokenization、拼接与 sequence packing。

> [!warning] 数据量并非越大越好
> 大量低质量、重复或错误数据会浪费算力，并加重记忆、偏见和幻觉。预训练的关键是**有效 token 的质量、多样性与配比** 。

---

#### [Q7] 为什么预训练数据需要去重？

去重主要解决以下问题：

- **避免重复样本浪费计算预算**；
- **防止高频重复来源主导模型分布**；
- **降低训练集与评测集污染**；
- **减少模型逐字记忆与隐私泄露风险**；
- **提高每个 token 所包含的有效信息量** 。

常见方法包括精确哈希、MinHash/LSH、n-gram 相似度和语义去重。

> [!note] 去重的权衡
> 去重过弱会保留大量模板与转载内容；去重过强则可能误删合理复现、固定表达或少数语言数据。因此通常需要按数据域设置不同阈值。

---

#### [Q8] 预训练中的一个样本是如何构造的？

原始文档经过 tokenizer 转为 token ID，再被拼接或切分为固定长度序列。

例如：

```text
Input:  [BOS, x1, x2, x3, x4]
Label:  [x1,  x2, x3, x4, EOS]
```

训练时使用 teacher forcing：一次前向计算并行预测所有位置的下一个 token，而不是像推理时那样逐 token 串行生成。

多个短文档可以通过 **sequence packing** 填充进同一上下文窗口，以减少 padding 和计算浪费；文档之间通常用 EOS 等特殊 token 分隔。

---

#### [Q9] 预训练时有哪些核心监控指标？

常见指标包括：

- **Training / Validation Loss**；
- **Perplexity（困惑度）**：$\mathrm{PPL}=\exp(\mathcal{L})$；
- **Gradient Norm、学习率与参数范数**；
- **吞吐量**：tokens/s、MFU 等；
- **数值稳定性**：NaN、Inf、loss spike；
- **下游能力评测**：知识、推理、代码、多语言等；
- **数据质量与污染检查** 。

> [!warning] Loss 更低不一定代表模型全面更好
> Loss 只衡量对验证分布的 token 预测能力。数据污染、领域偏置或过度拟合都可能使 loss 改善，却不提升真实任务能力，因此必须结合下游评测。

### 有监督微调 SFT

#### [Q10] 什么是有监督微调（SFT）？

SFT（Supervised Fine-tuning）是在预训练模型上，使用人工或合成的输入—目标回答数据继续训练。

底层目标通常仍是 next-token prediction：

$$
\mathcal{L}_{\mathrm{SFT}}
=
-\sum_{t\in\mathcal{T}_{\mathrm{response}}}
\log p_\theta(y_t\mid x,y_{<t})
$$

其中 $x$ 是 prompt，$y$ 是目标回答。SFT 的核心作用包括：

- 学会理解和遵循指令；
- 学习问答、对话和任务格式；
- 调整回答风格、长度与结构；
- 激活和组织预训练中已有的知识与能力。

---

#### [Q11] SFT 的训练数据格式是什么？

最简单的数据格式是 **Instruction → Response**：

```json
{
  "instruction": "写一首关于鹈鹕的打油诗。",
  "response": "从前有只鹈鹕鸟……"
}
```

带额外输入时可以表示为：

```json
{
  "instruction": "总结下面的文本。",
  "input": "待总结的原文……",
  "response": "总结结果……"
}
```

聊天模型通常使用多轮 messages 格式：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个简洁的助手。"},
    {"role": "user", "content": "什么是过拟合？"},
    {"role": "assistant", "content": "过拟合是模型……"}
  ]
}
```

训练前会通过 **chat template** 将角色和内容序列化为模型实际读取的 token 序列。

---

#### [Q12] SFT 为什么通常只对 Assistant Response 计算 Loss？

对于 prompt token，其作用是提供条件；真正希望模型学习生成的是 assistant response。因此常将 system 和 user token 的 label 设为 `-100`，只对 assistant token 计算交叉熵。

这样做的优点是：

- 梯度更直接地优化回答行为；
- 避免浪费容量学习复述用户问题；
- 多轮对话中可以只监督 assistant 的回复。

但这不是绝对规则。若希望模型同时学习完整对话分布，也可以对所有 token 计算 loss；具体选择取决于数据格式和训练目标。

> [!important] Mask 不等于不读取 Prompt
> Prompt token 不计算 loss，但仍参与注意力和条件建模。模型依然根据 prompt 预测回答。

---

#### [Q13] SFT 数据质量为什么往往比数量更重要？

SFT 数据规模远小于预训练数据，而且每个样本都在直接塑造模型的回答行为。少量错误、冗长或模板化样本可能被模型明显模仿。

高质量 SFT 数据应具备：

- 指令清楚、回答正确；
- 任务和表达方式多样；
- 难度与目标用户场景匹配；
- 拒答边界、格式和风格一致；
- 尽量减少答案泄漏、冲突标注和模板噪声。

==预训练主要追求广泛覆盖；SFT 更强调示范质量、任务多样性和行为一致性。==

### 预训练与 SFT 对比

#### [Q14] Pre-training 与 SFT 有哪些相同点和不同点？

**相同点：**

- 通常都使用 token-level cross-entropy；
- 对 Decoder-only LLM 而言，本质上都在做 next-token prediction；
- 都可以使用 teacher forcing 和相同的 Transformer 主干。

**不同点：**

| 对比项 | Pre-training | SFT |
| --- | --- | --- |
| 训练起点 | 通常随机初始化 | 已预训练模型 |
| 数据规模 | 极大 | 相对较小 |
| 数据形式 | 自然文本、代码等连续语料 | 指令—回答或多轮对话 |
| 标签来源 | 数据中的下一个 token 自动产生 | 人工或模型构造的目标回答 |
| Loss 范围 | 通常对所有有效 token | 常只对 response token |
| 核心目的 | 学习知识和通用能力 | 学习任务接口与回答行为 |
| 典型产物 | Base Model | Instruct / Chat Model |
| 学习率（峰值，经验量级） | 从头预训练常见约 $10^{-4}\sim10^{-3}$；大模型常落在 $1.5\times10^{-4}\sim3\times10^{-4}$ | 全参数 SFT 常见约 $10^{-6}\sim5\times10^{-5}$；LoRA 可使用更大的学习率，如 $10^{-5}\sim2\times10^{-4}$ |

> [!note] 学习率不能脱离训练配置比较
> 上述只是常见量级，不是固定规则。最优学习率还受模型规模、全参数或 PEFT、batch size、token 数、优化器和 scheduler 影响。以 LLaMA 2 为例，其从头预训练峰值学习率按模型规模约为 $1.5\times10^{-4}\sim3\times10^{-4}$，SFT 使用 $2\times10^{-5}$。SFT 从一个已经较好的参数点出发，数据又小而窄，因此通常使用更小的步长以避免破坏已有能力。

> [!tip] 面试中的关键回答
> 两者的**数学形式可能相同**，真正的差异主要在训练起点、数据分布、loss mask、数据规模和优化目的，而不是“一个预测下一个词、另一个不预测”。

---

#### [Q15] SFT 能给模型注入新知识吗？

**可以，但通常不是大规模知识注入的最高效方式。**

SFT 可以让模型记住少量事实、规则和领域范例，但其主要目标是学习如何完成任务。如果需要系统性补充大量领域知识，通常更适合：

- Continued Pre-training / Domain-Adaptive Pre-training；
- 检索增强生成（RAG）；
- 工具调用或外部数据库。

SFT 更适合教会模型：**何时使用知识、如何组织答案、以何种格式回答。**

不同需求对应的方法如下：

| 需求 | 更合适的方法 | 原因 |
| --- | --- | --- |
| 系统性写入大量、相对稳定的领域知识 | Continued Pre-training / DAPT | 能从大量无标注领域文本中获得密集 token 监督，并学习领域语言分布 |
| 知识经常变化、要求可追溯或不能写入参数 | RAG / 搜索 / 数据库 | 更新快、可引用来源，也便于删除和纠错 |
| 注入少量精确事实 | SFT、知识编辑或少量继续预训练 | 成本较低，但应评测泛化、冲突与遗忘 |
| 教模型在任务中正确调用知识 | SFT + 偏好对齐 | 重点是任务流程、格式、边界和行为 |

**Continued Pre-training（继续预训练，CPT）** 是一个上位概念：从已有 Base Model 出发，继续使用语言建模目标在新语料上训练，而不是随机初始化。它可以用于补充新时期数据、代码、数学、多语言、长上下文或专业领域知识，通常仍对连续文本中的大量 token 计算 next-token loss。与 SFT 相比，它的数据不必被逐条改造成问答对，监督更密集，适合系统性吸收大规模知识；代价是训练成本较高，并可能造成灾难性遗忘，因此常混入一部分通用语料、降低学习率并做通用能力回归评测。

**Domain-Adaptive Pre-training（领域自适应预训练，DAPT）** 是 CPT 的一种：继续在医学、法律、金融、芯片等某个目标领域的大规模无标注语料上做预训练，让模型适应该领域的术语、文体、实体关系和知识分布。它强调的是“目标领域”。类似地，**Task-Adaptive Pre-training（TAPT）** 使用更小但与具体下游任务分布更接近的无标注语料，强调“目标任务”。典型流程是：

$$
\text{通用 Base Model}
\rightarrow
\text{DAPT/CPT：补领域知识与表示}
\rightarrow
\text{SFT：学习任务接口}
\rightarrow
\text{偏好/安全对齐}
$$

### 对齐 Alignment

#### [Q16] 什么是 LLM 对齐（Alignment）？

对齐是让模型的**实际行为** 更符合人类意图、偏好、规范和安全要求的过程。预训练目标是“预测互联网文本中的下一个 token”，但部署目标通常是“按用户意图正确、安全、可控地完成任务”，二者并不天然一致。

对齐常概括为 **3H**：

- **Helpful**：有帮助并正确完成任务；
- **Honest**：不伪装能力，不刻意编造；
- **Harmless**：减少危险、歧视和有害输出；

实际系统还关注：

- **Instruction-following**：遵循用户和系统指令；
- **Controllable**：格式、风格和行为边界可控。

**RLHF** 是 **Reinforcement Learning from Human Feedback**：

- **R = Reinforcement**：用奖励信号强化更好的行为；
- **L = Learning**：根据奖励更新策略模型；
- **HF = Human Feedback**：奖励信号源自人类对候选回答的排序、评分或反馈。

经典 RLHF 先用人类偏好训练 Reward Model，再通过 PPO 等强化学习算法优化语言模型，同时用 KL 约束防止策略偏离参考模型过远。

常见对齐手段：

| 手段 | 含义 | 主要作用 |
| --- | --- | --- |
| SFT | 用高质量“指令—理想回答”做监督学习 | 示范应当如何回答，建立指令遵循和输出格式 |
| RLHF | 从人类反馈中学习奖励，再用 RL 优化模型 | 学习难以写成唯一标准答案的人类偏好 |
| RLAIF | 用 AI 按规则或“宪法”评价回答，替代或补充人工反馈 | 降低偏好标注成本、扩大覆盖范围 |
| DPO | 直接提高 chosen 相对 rejected 回答的概率，无需显式 Reward Model 和在线 PPO | 用更简单稳定的离线训练实现偏好优化 |
| 安全微调 | 使用拒答、风险识别、边界处理等样本训练 | 降低有害输出，同时尽量避免无关拒答 |
| 红队评测 | 主动构造越狱、欺骗、偏见和高风险测试 | 发现失效模式；它本身是评测/数据闭环，不是单独的训练算法 |
| 推理时防护 | 系统提示、输入输出过滤、权限隔离、工具审批等 | 在部署阶段提供纵深防御 |

> [!warning] 对齐不等于 RLHF
> RLHF 只是对齐方法之一。SFT、规则奖励、DPO、系统提示、RAG、工具权限和安全过滤同样属于完整对齐系统的一部分。

---

#### [Q17] 对齐与能力训练有什么区别？

- **能力训练** 关注模型“能不能完成任务”，例如是否会写代码、解数学题；
- **对齐训练** 关注模型“何时、以何种方式完成任务”，例如是否遵循要求、诚实表达不确定性并避免危险行为。

为什么“何时、以何种方式”很重要？因为一个模型即使具备某项能力，也可能：

- 用户没有要求时擅自调用工具、执行操作或泄露信息；
- 忽略格式、角色、权限和业务约束，导致答案无法使用；
- 不知道时仍自信编造，或为了迎合偏好而附和错误前提；
- 面对危险请求不设边界，面对正常请求却过度拒答；
- 找到“获得高奖励”的捷径，而不是真正完成用户目标。

因此，对齐不是单纯让回答“更好听”，而是把潜在能力转化为**可靠、可控、符合目标的行为** 。其目的大致分为：

1. **意图对齐**：正确理解并遵循 system / developer / user 指令及优先级；
2. **偏好对齐**：改善帮助性、相关性、简洁度、风格和交互体验；
3. **真实性与校准**：减少编造，在不确定时说明限制，必要时检索或引用证据；
4. **安全与价值边界**：降低违法、有害、歧视、隐私泄露和滥用风险；
5. **可控性与规范遵循**：稳定输出指定格式，正确使用工具并遵守权限、政策和领域规范。

典型使用场景包括：开放域聊天助手、客服与企业 Agent、工具调用和自动执行系统、医疗/法律/金融等高风险任务、安全拒答、结构化输出，以及任何“答案不只有唯一标签、但存在明显质量或风险偏好”的任务。若主要问题是模型根本不会某项知识或技能，应优先做预训练、CPT 或能力数据训练；若模型会做但行为不稳定、不可控，则应使用 SFT、偏好优化和安全对齐。

两者并非完全独立：

- 能力不足时，仅靠对齐无法让模型稳定完成复杂任务；
- 对齐过强或数据不当可能抑制原有能力，产生 alignment tax；
- 高质量后训练也可能激活预训练中潜在但未稳定表现出的能力。

### 深入理解与常见追问

#### [Q18] 为什么 Base Model 不直接用指令数据从头训练？

指令数据规模有限且成本高，难以覆盖语言、知识和世界分布。若从头只用指令数据训练：

- 模型缺乏通用语言与知识基础；
- 容易过拟合少量任务模板；
- 数据和人工标注成本无法扩展；
- 大量 token 级监督信息被浪费。

更高效的分工是：

1. 用海量自监督数据学习通用能力；
2. 用少量高质量 SFT 数据定义任务接口；
3. 用偏好或奖励信号进一步塑造行为。

---

#### [Q19] 为什么 SFT 后模型会更会对话，但有时基础能力反而下降？

可能原因包括：

- SFT 数据分布过窄，导致灾难性遗忘；
- 大量模板化回答使输出多样性下降；
- 学习率过高或训练轮数过多；
- 安全拒答数据比例过高，导致过度拒答；
- 只优化回答风格，却缺少能力保持数据。

常见缓解方式：

- 降低学习率和训练轮数；
- 混入通用、代码、数学等能力保持数据；
- 使用 LoRA 等参数高效微调；
- 对 Base Model 与 SFT Model 进行多维回归评测；
- 调整数据配比，而不是只扩大 SFT 数据量。

---

#### [Q20] Chat Template 为什么重要？

Chat Template 定义 system、user、assistant 消息如何转换为 token 序列，包括角色标记、分隔符和终止符。

它的重要性在于：

- SFT 时模型学习的是特定模板下的条件分布；
- 推理模板与训练模板不一致会造成性能下降；
- EOS 或 assistant 起始标记错误可能导致不停生成、角色混乱或重复输出；
- 不同模型家族通常不能随意共用模板。

> [!important] 工程结论
> Tokenizer 相同不代表 Chat Template 相同。部署时必须使用与该 checkpoint 后训练阶段一致的模板。

---

#### [Q21] 面试中如何用一分钟概括 LLM 的训练流程？

> LLM 首先在海量文本和代码上通过 next-token prediction 进行预训练，学习语言、知识和通用能力，得到 Base Model；必要时再通过继续预训练增强领域、数学、代码或长上下文能力。之后使用指令—回答数据进行 SFT，让模型学会理解指令和按格式回答。最后通过 RLHF、DPO、RLAIF 等偏好对齐方法改善帮助性、安全性和回答质量，并结合能力、安全评测及推理优化后部署。预训练与 SFT 的底层都可能是 next-token prediction，核心区别在于数据、训练起点、loss 范围和优化目的。

#### [Q13] 微调时如何防止遗忘预训练知识（灾难性遗忘）？

微调时"遗忘"预训练知识的现象称为**灾难性遗忘（Catastrophic Forgetting）**，主要有以下防御手段：

1. **参数高效微调（PEFT / LoRA）**：只更新极少数新增参数（如低秩矩阵 $A, B$），预训练权重 $W_0$ 保持冻结，从结构上限制对原有知识的破坏。LoRA 相比全参数微调遗忘程度更低，是目前最主流的方法。

2. **弹性权重固化（EWC, Elastic Weight Consolidation）**：在旧任务训练完成后，以旧参数 $\theta^*$ 为中心，用 Fisher 信息近似旧任务 loss 在局部的曲率；新任务训练时，重要参数不允许移动太远：
   $$
   \mathcal{L} = \mathcal{L}_{\text{new}} + \lambda \sum_i F_i (\theta_i - \theta_i^*)^2
   $$
   其中 $\theta_i^*$ 是旧任务参数，$F_i$ 是对应的 Fisher 重要性权重。实践中通常只保存 Fisher 的对角线，并在旧数据 $D_{\text{old}}$ 上估计：
   $$
   F_i
   \approx
   \frac{1}{|D_{\text{old}}|}
   \sum_{(x,y)\in D_{\text{old}}}
   \left(
   \frac{\partial \log p_{\theta^*}(y\mid x)}
   {\partial \theta_i}
   \right)^2
   $$
   如果某个参数轻微变化就会显著改变旧任务样本的 log-likelihood，那么其 score gradient 的平方期望较大，$F_i$ 就较大，说明该参数对旧任务更敏感、应受到更强保护。注意：Fisher 衡量的是**旧任务分布附近的局部敏感度**，不是某个参数中“存了多少知识”；对角近似还忽略了参数之间的相关性。对超大 LLM 保存和估计 Fisher 仍有成本，因此 EWC 更常作为持续学习的经典思想或近似正则，而非所有 LLM 微调的默认方案。

3. **RLHF 中的 KL 散度惩罚**：在 PPO 优化时对策略与参考模型之间加 KL 惩罚，避免模型在 RLHF 过程中偏离预训练分布过远：
   $$
   r_{\text{total}} = r_{\text{reward}} - \beta \cdot D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})
   $$
   DPO 将此项内化进损失函数，不需要显式计算。

4. **数据回放（Replay）**：在微调数据中混入少量预训练数据（如通用文本、代码），让模型在学习新任务的同时维持对通用知识的激活。InstructGPT 的 PPO-ptx 变体就在 RLHF 更新中加入了预训练梯度，以减轻公开 NLP 任务上的性能回退。

5. **正交子空间学习（O-LoRA, EMNLP 2023）**：核心思想是把连续任务的参数更新放入尽量互不重叠的子空间。普通 LoRA 对权重加入低秩更新 $\Delta W_t=B_tA_t$；O-LoRA 为新任务增加新的低秩适配器，并加入正交约束，使新任务的 LoRA 子空间与此前任务的子空间尽量正交。直观上，若旧任务主要使用方向 $u$ 表示知识，新任务就尽量沿与 $u$ 垂直的方向更新，从而减少参数干扰。

   需要区分两个相近概念：
   - **正交梯度投影**：先估计旧任务梯度张成的子空间，再把新梯度投影到其正交补空间，例如 $g_{\perp}=(I-UU^\top)g$；
   - **O-LoRA**：不必保存历史样本或完整历史梯度，而是让不同任务的低秩 LoRA 子空间保持正交。

   “正交”只能减少一阶或子空间层面的冲突，不能严格保证旧任务性能完全不下降：任务可能共享特征，子空间容量也会随着任务增加而耗尽。它尤其适合**任务按顺序到达、不能保存旧数据、又希望为每个任务增加少量参数** 的持续学习场景；单次普通 SFT 通常不必使用。

#### [Q14] P-Tuning 是什么？和 LoRA、Prompt Tuning 有什么区别？

P-Tuning（Liu et al., 2021，清华等）属于 **Soft Prompt / 参数高效微调**：用梯度学习一组不对应真实词表 token 的连续向量，引导预训练模型完成任务。

> [!important] 先纠正一个容易混淆的说法
> “把虚拟 token 插入每一层”描述的是 **P-Tuning v2**；P-Tuning v1 只在** 输入 embedding 层**使用连续提示。

##### 1. 什么是 Soft Prompt？

普通 hard prompt 是人能读懂的离散 token，例如 `请判断下面评论的情感`。Soft Prompt 则是：

$$
P=[p_1,\ldots,p_m]\in\mathbb R^{m\times d}
$$

其中每个 $p_i$ 都是与 hidden size 相同的连续向量，但通常不对应词表中的某个单词。它是 `nn.Parameter`，因此**可导、可训练**；loss 的梯度穿过冻结的 Transformer 反传到 $P$，优化器只更新这些允许训练的参数。

##### 2. Prompt Tuning：只在输入层加 Soft Prompt

最常见的做法是把 $m$ 个 Soft Prompt 向量放在真实输入 embedding 的**前面**：

$$
H_0=[P;E(x_1),\ldots,E(x_n)]
$$

放在前面便于后续真实 token 通过因果 Attention 看到 prompt。不过“Soft Prompt 必须位于最前面”不是数学规定：在双向模型中也可以按任务模板插在中间；关键是 Attention mask 必须允许目标 token 使用这些向量。

##### 3. P-Tuning v1：输入层 Prompt + Prompt Encoder

P-Tuning v1 不只是简单地学习彼此独立的 prompt 向量，而是先把虚拟 token 的初始 embedding 输入一个小型 **Prompt Encoder**：

$$
z_1,\ldots,z_m
\xrightarrow{\mathrm{BiLSTM+MLP}}
p_1,\ldots,p_m
$$

这里的 Encoder 不是另一个完整的 BERT，而是一个较小的 BiLSTM + MLP。它的作用是让各 prompt 位置相互通信，以较平滑、相关的方式生成最终连续提示，缓解直接在离散的 embedding 空间中优化不稳定的问题。

- 虚拟 token 的底层 embedding 和 Prompt Encoder 都可以是可训练参数；
- Encoder 输出的 Soft Prompt 对 loss 可导；
- 训练结束后保存任务专属的 Prompt Encoder / Prompt 参数；
- 连续 prompt 可以和离散模板词混合，位置由模板决定，不一定全部放在句首。

在“参数高效”设置下，基础模型被冻结，只训练 Prompt 相关参数；但 **P-Tuning v1 原论文也研究了连同 backbone 一起更新的设置**，所以“P-Tuning 在定义上绝对不修改任何模型权重”并不严谨。

##### 4. P-Tuning v2：每层加入 Deep Prompt

P-Tuning v2 将任务提示从输入层扩展到 Transformer 的每一层。概念上，第 $\ell$ 层都有自己的前缀：

$$
H_\ell'=[P_\ell;H_\ell]
$$

工程实现常把 $P_\ell$ 表示为该层 Attention 的额外 **prefix Key / Value**，而不是真的把普通 token 反复插入并传到下一层。因此更准确的理解是：** 每层 Attention 都能直接读取一组可学习的任务前缀。**

标准 P-Tuning v2 实验冻结 Transformer backbone，训练：

- 每层的 Deep Prompt / Prefix 参数；
- 可选的重参数化 MLP；
- 任务需要时的轻量分类头。

##### 5. v2 是否“去掉了 Encoder”？

**不是必然去掉，而是把重参数化 Encoder 变成可选项。** v2 论文发现 MLP 对某些数据集有帮助，对另一些数据集作用很小甚至有负作用。因此核心改进不是“删掉 Encoder”，而是：

1. 从只影响输入层，改为直接影响每一层；
2. 增大每个任务可用的提示容量；
3. 针对 NLU 调整 prompt length、分类头和多任务初始化等实现细节。

v1 使用 BiLSTM + MLP，主要是缓解输入层 prompt 难优化；v2 的每层 prompt 已经能直接影响深层表示，因此不再必须依赖统一的 Prompt Encoder。

##### 6. “中小模型”有多大？

这是相对于当时 10B 级模型而言。P-Tuning v2 论文中：

- **中等规模** 明确指约 **100M–1B**；
- 实验覆盖约 **330M、2B 到 10B**；
- Prompt Tuning / v1 在小于约 10B 时往往明显落后于全参数微调，而 v2 在这些规模上显著缩小差距。

因此这里不是指今天口语中的“1B–7B 小型 LLM”这一固定分类，而是论文实验语境中的模型规模。

##### 7. 每层 Soft Prompt 有多少参数？

设层数为 $L$、每层 prompt 长度为 $m$、hidden size 为 $d$：

- 若每层直接保存 $m$ 个 hidden vectors，约为  
  $$
  N_{\text{prompt}}=Lmd
  $$
- 若实现为独立的 Attention Key 和 Value prefix，约为  
  $$
  N_{\text{KV-prefix}}=2Lmd
  $$

多头 Attention 不需要再额外乘 head 数，因为所有 head 的总维度仍为 $d$。可选 MLP、分类头等参数需要另外计算。

例如：

| 模型配置 | $m$ | $Lmd$ | $2Lmd$ |
| --- | ---: | ---: | ---: |
| BERT-large：$L=24,d=1024$ | 20 | 约 0.49M | 约 0.98M |
| BERT-large：$L=24,d=1024$ | 100 | 约 2.46M | 约 4.92M |
| 7B 级模型示例：$L=32,d=4096$ | 20 | 约 2.62M | 约 5.24M |

绝对数量可以达到几百万，但相对数亿至数十亿 backbone 参数仍然很小。论文报告每个任务训练约 **0.1%–3%** 参数；模型越小、prompt 越长，占比越高。其代价还包括：每层 prefix 会增加 Attention 的有效序列长度，因此也有一定推理时延和 KV cache 开销。

| 方法 | 可训练参数位置 | 是否改变模型架构 | 适用场景 |
| --- | --- | --- | --- |
| Full Fine-tuning | 全部参数 | 否 | 资源充裕，效果最优 |
| LoRA | 每层的低秩矩阵 $A, B$ | 否（并联添加） | 主流 PEFT，通用 |
| Prompt Tuning | 输入层 Soft Prompt | 否 | 参数最少；模型达到约 10B 量级后更接近全参数微调 |
| P-Tuning v1 | 输入层连续提示 + BiLSTM/MLP Prompt Encoder | 否 | 知识探测、NLU；可冻结或更新 backbone |
| P-Tuning v2 | 每层 Deep Prompt / Prefix，可选 MLP | 否 | 论文中在约 330M–10B 的 NLU 模型上有效 |
| Prefix Tuning | 每层 KV 前缀 | 否 | 生成任务 |

> [!summary] 一句话区分
> **Prompt Tuning**：只学输入层前面的向量；  
> **P-Tuning v1**：输入层连续提示由一个小 Encoder 生成；  
> **P-Tuning v2**：让每层都能直接读取自己的连续提示，Encoder/MLP 只是可选重参数化。
