### Decoder-Only 架构

#### [Q1] 为什么今天大模型几乎都用 causal attention?

1. 更深层原因是 train-test consistency。预训练和下游任务测试的时候，使用的形式更加一致。这让它特别适合大规模互联网语料预训练，也就是训练效率问题。
在翻译、摘要、问答、信息抽取这类任务里，其实 encoder-decoder 架构更加天然适合，所以小中型模型时代，T5/BART 这类很常用。但是在当今超大规模预训练需求下，统一接口、数据规模、推理生态更重要。

2. prefix decoder 本质不是结构改变，而是 mask engineering. 也就是说，它让 prefix 区域双向可见、让生成区域继续自回归。简而言之，通过 mask 人为规定不同 token 的权限。

---

#### [Q2] 为什么 encoder-decoder 天然可以支持输入输出序列长度不同？其他两个架构做得到吗？

*encoder-decoder:*

1. encoder 只负责把输入$x$编码成一组 memory，长度为$|x|$。decoder 每step生成一个 token。有多少 step 就有多少次decoder rollout 步数，即多少个输出。输入和输出是两个角色。在形式上直接就是：输入先完整编码，输出再逐步生成。

2. encoder 处理好的token，会产生 hidden states，并作为 encoded memory，在 decoder 部分通过 cross-attention 直接读取，无需作为 decoder 的输入。所以 encoded memory 不是 decoder 的主序列里的历史位置，因此 encoder 的输入和 decoder 的输出长度没有关系。

*causal decoder*

1. causal attention 的输入输出只是同一串 token 里的不同位置。没有显式区分输入和生成的内容。

2. 在 causal decoder 和 prefix decoder 里，prefill 部分的 token 也都会正常过一遍网络，各自产生一份 hidden state，和 token 是一一对应的。然后这些位置的 K/V 会缓存下来。后续 decode 只是从这个前缀状态继续往后追加。

*causal decoder vs. prefix decoder 的训练时区别*

在 causal LM 中，通常每个位置都可用于 next-token loss。在某些 prefix LM / seq2seq-style masking 里，prefix 部分虽然也有 hidden states，但可能不参与 loss，或者只作为条件，不要求预测 prefix 自己后面的 token。

---

#### [Q3] 为什么 prefix decoder 训练效率往往低于纯 causal？

1. attention mask 更不规则，算子更不友好。纯 causal 是整块严格下三角，实现成熟、fused kernel 与 FlashAttention 一类优化最自然，cache / packing / padding 也最好统一。prefix 架构中的 token 是混合可见性：prefix 内双向、target 看 prefix、target 内单向，不再是单一下三角，高效 kernel 与工程路径通常不如纯 causal 顺手。

2. 监督更稀疏，token 利用率更低。纯 causal LM 里整条序列几乎每个位置都能贡献 next-token loss；prefix 里双向区往往不能按同一套自回归范式做预测监督，长 prefix、短 target 时大量 token 只做条件编码、少数位置承担生成 loss，单位 step 的有效学习信号更稀疏、更少。纯 causal 可把整段都纳入 next-token 学习，密度更高。

3. 大模型时代这点更致命，因为预训练核心指标是每单位算力换多少有效训练信号；规模放大后，prefix 路线的性价比通常不如统一 causal。

---

### Encoder-Decoder 架构

#### [Q4] 为什么去噪自编码器往往更难实现或训练更慢？

1. 数据构造复杂。要先按规则破坏输入，再从残缺输入恢复原文；causal LM 通常原文右移一位即可训练，构造简单。

2. 输入输出不再天然对齐。causal 是同一序列上的移位预测，天然一一对应；去噪里输入是损坏后的 $\tilde{x}$，目标落在原文或被 mask/替换的位置上，长度与有效监督位置都可能和输入错位，实现上要多做 target 拼接、label 对齐与 special token 规则。

3. 训练效率低。不少去噪预训练用 encoder-decoder 或 prefix 式 mask，不是纯 causal decoder-only，工程优化与吞吐往往不如单纯的 decoder-only。（见 Q3）

4. 单位序列上的核心监督更稀。causal LM 几乎每个位置都在预测下一 token；去噪里通常只有「被破坏、被要求重建」的那部分直接承担主要 loss。

5. 训练目标与常见推理形态易不一致。causal 训练与续写生成是同一件事；去噪训练偏填空/修复，下游却常要做自由生成，迁移与对齐成本更高。

#### [Q5] Encoder-decoder 的模型如何预训练？

bert 的预训练方法是 mask 掉一部分 word，让 decoder 重建原文。
更适合翻译、QA 任务。
