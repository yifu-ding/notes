### 多模态对齐基础

#### [Q1] 多模态对齐是什么意思？

多模态对齐（multimodal alignment）指把不同模态中语义相关的元素映射到可以互相匹配的表示空间。例如图像中的“狗”区域应该和文本中的 “dog” token 或句子语义接近。

对齐可以发生在不同粒度：

| 粒度 | 例子 | 特点 |
| --- | --- | --- |
| 样本级对齐 | 一张图和一句描述匹配 | 粗粒度，适合检索和对比学习 |
| 区域-词对齐 | 图像区域和文本词语匹配 | 更细粒度，适合理解具体对象 |
| token-level 对齐 | 不同模态 token 逐位置交互 | 表达能力强，但对数据和计算要求更高 |
| 语义级对齐 | 不要求位置对应，只要求语义一致 | 更灵活，常用于生成和推理 |

常见训练目标包括：

1. **对比学习。** 拉近匹配的图文样本，推远不匹配样本。CLIP、ALIGN、ALBEF 都使用了这个思想。
2. **图文匹配。** 判断图像和文本是否匹配，常用于融合 encoder 的预训练。
3. **掩码预测。** 给定部分模态，预测被遮盖的 token、patch 或 region feature。
4. **生成式目标。** 给定图像生成 caption，或给定图文上下文生成答案。
5. **区域-词对齐目标。** 通过显式或隐式约束，让词和图像区域建立更细粒度的对应关系。

对齐不等于融合。对齐强调“不同模态的语义能不能对应起来”，融合强调“如何把信息组合成一个对任务有用的表示”。CLIP 更偏对齐，UNITER / LXMERT / BLIP 更偏对齐之后进一步融合。

---

#### [Q2] 多模态融合一般分成哪几类？

多模态融合通常可以分成三类：**Early Fusion**、**Middle Fusion** 和 **Late Fusion**。

| 类型 | 核心做法 | 融合发生位置 | 典型特点 | 代表方法 |
| --- | --- | --- | --- | --- |
| Early Fusion | 把不同模态 token 拼成一个统一序列 | 输入端或很早的层 | 交互充分，但序列长、模态差异容易互相污染 | VisualBERT、VL-BERT、UNITER、ViLT |
| Middle Fusion | 先各自编码，再在中后层融合 | 中间层到高层 | 兼顾 modality-specific pattern 和 cross-modal dependency | ViLBERT、LXMERT、ALBEF、BLIP、BLIP-2 |
| Late Fusion | 每个模态先独立编码，最后再融合或对齐 | 高层表示或输出端 | 单模态 encoder 稳定、可扩展，但细粒度交互较弱 | CLIP、ALIGN、LiT、dual-encoder retrieval |

> 多模态融合的关键问题不是“能不能把 token 拼起来”，而是要决定：哪些层负责学习 modality-specific pattern，哪些层负责学习 cross-modal dependency。

### Early Fusion

#### [Q3] 什么是 Early Fusion？

Early Fusion 指把不同模态的数据在输入端就转成 token，并拼接成一个统一序列，然后送入同一个共享 backbone。例如：

$$
[x_{text}, x_{image}, x_{audio}, \ldots] \rightarrow \text{shared Transformer}
$$

对视觉-文本任务，常见形式是：

$$
[\text{[CLS]},\ x_1^{text},\ldots,x_m^{text},\ x_1^{image},\ldots,x_n^{image}]
\rightarrow \text{single-stream Transformer}
$$

这里的 image token 可以是 object region feature，也可以是 image patch embedding。模型通常会加入 text / image 的 type embedding、position embedding 或 region position embedding，让 Transformer 知道每个 token 来自哪个模态。

它的特点是：

1. **所有 token 走同一个 backbone。** 不同模态共享同一组 Transformer 层。
2. **所有 token 使用同一套 Attention 和 FFN。** 模型没有显式区分不同模态的计算路径。
3. **跨模态交互从低层就开始。** 任意一个文本 token 从第一层开始就可以关注图像 token，反之亦然。
4. **融合方式最直接。** 把多模态问题转成“带 modality embedding 的长序列建模”问题。

---

#### [Q4] Early Fusion 有什么优点和缺点？

Early Fusion 的优点是：

1. **实现简单。** 只需要把不同模态 token 对齐并拼接，然后复用标准 Transformer。
2. **跨模态交互充分。** 从第一层开始，不同模态之间就可以通过 Self-Attention 通信。
3. **每一层都能做融合。** 低层、中层、高层都可以学习跨模态关系。
4. **适合细粒度理解任务。** 例如视觉问答、视觉推理、图文匹配等任务常常需要词和区域之间的细粒度对应。

Early Fusion 的缺点也很明显：

1. **序列变长，Attention 成本高。** 标准 Attention 的复杂度随序列长度二次增长；图像 patch 或视频帧会显著增加 token 数。
2. **不同模态统计分布差异大。** 文本是离散符号，图像 patch 更偏局部空间结构，共用同一路径可能训练不稳定。
3. **缺少 modality-specific inductive bias。** 模型需要自己学习每个模态的局部结构、尺度差异、噪声模式和依赖关系。
4. **容易出现模态主导。** 信息量更大或 token 数更多的模态可能在训练中压制其他模态。
5. **不一定适合大规模检索。** 如果每对图文都要过一个融合 Transformer，检索时无法提前离线缓存单独的图像向量和文本向量。

Early Fusion 更适合输入长度可控、需要细粒度跨模态交互、并且不强依赖大规模向量检索的场景。

---

#### [Q5] Early Fusion 有哪些经典视觉-文本方法？

1. **VisualBERT：A Simple and Performant Baseline for Vision and Language，2019。**

   VisualBERT 是 single-stream vision-language Transformer 的代表。它把文本 token 和图像 region feature 拼成一个序列，送入类似 BERT 的 Transformer，通过 Self-Attention 隐式学习词和图像区域之间的对齐关系。它的重点不是设计复杂的双流结构，而是说明“把视觉区域当成 token 接到 BERT 里”本身就是一个很强的 baseline。

   VisualBERT 的典型训练目标包括基于图文数据的 masked language modeling 和图文匹配。它适合用来理解 Early Fusion 的核心思想：**把图像区域和文本 token 放到同一个 Transformer 中，让 Self-Attention 自己学对齐。**

2. **VL-BERT：Pre-training of Generic Visual-Linguistic Representations，2019。**

   VL-BERT 也是 unified single-stream 架构。它把视觉内容和语言内容一起输入 Transformer，不显式限制 attention pattern，让两种模态在同一个 Transformer 中自由交互。它强调学习通用的 visual-linguistic representation，可以迁移到视觉问答、视觉常识推理等任务。

   VL-BERT 的意义在于，它进一步推动了“视觉 token + 文本 token + BERT-style pretraining”的路线，说明 BERT 的 masked modeling 思路可以扩展到视觉-语言场景。

3. **⭐ UNITER：UNiversal Image-TExt Representation Learning，2020。**

   UNITER 是 early-fusion VLP 里非常重要的里程碑。它使用 single-stream Transformer 学习统一的 image-text representation，并在大规模图文数据上预训练。相比早期方法，UNITER 系统化地组合了多个预训练目标：Masked Language Modeling、Masked Region Modeling、Image-Text Matching，以及基于 Optimal Transport 的 Word-Region Alignment。

   UNITER 的重点是：不仅把图文 token 拼起来，还显式鼓励词和图像区域之间的细粒度对齐。它在 VQA、图文检索、视觉常识推理、视觉蕴含、referring expression 等任务上都很有代表性。

4. **ViLT：Vision-and-Language Transformer Without Convolution or Region Supervision，2021。**

   早期 VLP 很多依赖 Faster R-CNN 提取 region feature，视觉特征提取成本高。ViLT 直接使用 image patch embedding 和 text token 进入同一个 Transformer，去掉重型 object detector，使模型更简单、更快。

   ViLT 的意义在于，它把视觉-文本 Early Fusion 从“region feature + Transformer”推进到“patch token + Transformer”，更接近后来 ViT 风格的统一 token 建模。

### Middle Fusion

#### [Q6] 什么是 Middle Fusion？

Middle Fusion 是 Early Fusion 和 Late Fusion 之间的折中：先让每个模态通过若干层 modality-specific encoder 学习自己的低层 pattern，然后在中高层引入 cross-modal fusion。

一种常见形式是：

$$
\begin{aligned}
\text{image} &\rightarrow \text{vision encoder} \rightarrow h_{image} \\
\text{text} &\rightarrow \text{text encoder} \rightarrow h_{text}
\end{aligned}
\quad
\rightarrow \text{cross-modal fusion layers} \rightarrow \text{output}
$$

也可以理解成：

1. 每个模态先走若干层 modality-specific blocks；
2. 然后进入 shared blocks、cross-attention blocks 或 fusion blocks；
3. 在 fusion blocks 中通过 Cross-Attention、co-attention、gating 或 adapter 做跨模态交互。

典型结构可以写成：

```text
vision encoder: image tokens -> visual features
text encoder:   text tokens  -> textual features

fusion layers:
    text self-attn
    image self-attn
    text-to-image cross-attn
    image-to-text cross-attn
    FFN
```

Middle Fusion 的核心是：**低层保留模态专属结构，中高层再学习跨模态依赖。**

---

#### [Q7] Middle Fusion 有什么优点和缺点？

Middle Fusion 的优点是：

1. **兼顾单模态建模和跨模态交互。** 图像可以先学习局部视觉结构，文本可以先学习语言结构，然后再融合。
2. **比 Early Fusion 更稳定。** 不同统计分布不会从第一层开始强行共享所有参数。
3. **比 Late Fusion 更细粒度。** 融合层仍然可以让文本 token 关注图像区域或 patch，让图像 token 关注文本语义。
4. **容易接入预训练 encoder。** 可以使用已有 vision encoder 和 language encoder，再增加 cross-modal layers。
5. **适合理解和生成的混合任务。** 例如图文问答、图像描述生成、图文检索 reranking、多模态指令理解等。

Middle Fusion 的缺点是：

1. **结构比 Early / Late Fusion 更复杂。** 需要设计 fusion layer 放在哪些层、交互方向是什么、是否共享参数。
2. **训练和调参成本更高。** Cross-Attention、co-attention、多任务 loss 都会增加工程复杂度。
3. **推理速度可能较慢。** 如果每个图文 pair 都要经过融合层，大规模检索时仍然不如 dual encoder 高效。
4. **融合时机需要选择。** 融合太早会接近 Early Fusion，融合太晚又接近 Late Fusion。

> Middle Fusion 是视觉-文本理解任务中非常常见的折中方案：既不完全把模态混在一起，也不完全等到最后才合并。

---

#### [Q8] Middle Fusion 有哪些经典视觉-文本方法？

1. **⭐ ViLBERT：Pretraining Task-Agnostic Visiolinguistic Representations，2019。**

   ViLBERT 是 two-stream vision-language Transformer 的代表。它有两个独立分支：一个处理视觉 region feature，一个处理文本 token。两个分支不是一开始就拼接，而是在若干 co-attentional Transformer layers 中交互。

   它的核心思想是：视觉和语言各自保留独立流，同时通过 co-attention 让文本关注图像、图像关注文本。相比 single-stream Early Fusion，ViLBERT 更强调 modality-specific processing；相比 Late Fusion，它又不是只在最后拼接，而是在中间层反复交换信息。

2. **⭐ LXMERT：Learning Cross-Modality Encoder Representations from Transformers，2019。**

   LXMERT 明确拆成三个 encoder：object relationship encoder、language encoder 和 cross-modality encoder。前两个 encoder 分别建模视觉对象关系和语言语义，第三个 encoder 用 cross-attention 学习图文之间的对齐和推理关系。

   LXMERT 的预训练目标很丰富，包括 masked language modeling、masked object prediction、cross-modality matching 和 image question answering。它是理解 Middle Fusion 的经典例子：**先单模态编码，再进入跨模态 encoder。**

3. **ALBEF：Align Before Fuse，2021。**

   ALBEF 的名字就概括了核心思想：先 align，再 fuse。它先用 image encoder 和 text encoder 得到单模态表示，用 image-text contrastive learning 做全局对齐；然后再通过 multimodal encoder 进行 cross-modal fusion。

   ALBEF 的重要性在于，它指出直接把未对齐的视觉 token 和文本 token 交给融合 encoder 会比较困难，因此先用对比学习把图文表示拉到相近语义空间，再做更细粒度融合。它还使用 momentum distillation 来缓解 web 图文数据噪声。

4. **⭐ BLIP：Bootstrapping Language-Image Pre-training，2022。**

   BLIP 是统一视觉-语言理解和生成的代表性工作。它提出 Multimodal Mixture of Encoder-Decoder，可以在不同模式下工作：单模态 encoder 用于图文对齐，image-grounded text encoder 用于理解任务，image-grounded text decoder 用于生成任务。

   BLIP 的另一个关键贡献是 CapFilt：先用 captioner 为图像生成候选描述，再用 filter 去掉噪声描述，从而改善 web 图文数据质量。它不仅是融合结构上的方法，也是数据 bootstrapping 思路的代表。

5. **⭐ BLIP-2：Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models，2023。**

   BLIP-2 的核心是用轻量级 Q-Former 连接 frozen image encoder 和 frozen LLM。Q-Former 中的 learned query tokens 通过 Cross-Attention 从视觉特征中提取少量与语言相关的视觉信息，再把这些信息接到语言模型侧。

   它的意义在于：不再端到端训练巨大的视觉模型和语言模型，而是冻结强大的单模态模型，只训练一个桥接模块来缩小 modality gap。这种“frozen vision encoder + bridge module + frozen LLM”的范式后来被大量多模态大模型采用。

### Late Fusion

#### [Q9] 什么是 Late Fusion？

Late Fusion 指每个模态先用自己的 encoder 独立编码，得到各自的高层表示，最后再把这些表示用于融合、匹配、打分或预测。

形式上可以写成：

$$
\text{image} \rightarrow \text{image encoder} \rightarrow z_{image}
$$

$$
\text{text} \rightarrow \text{text encoder} \rightarrow z_{text}
$$

然后：

$$
s(z_{image},z_{text}) \rightarrow \text{matching score}
$$

或者：

$$
[z_{image},z_{text}] \rightarrow \text{fusion head} \rightarrow \text{prediction}
$$

Late Fusion 的核心思想是：**先把每个模态自己的表示学好，再在高层合并或对齐。** 在视觉-文本领域，dual encoder 是最典型的 Late Fusion：图像和文本分别编码成向量，只在最后通过 dot product、cosine similarity 或一个轻量 head 计算匹配程度。

---

#### [Q10] Late Fusion 有什么优点和缺点？

Late Fusion 的优点是：

1. **每个模态有自己的 encoder。** 不同模态可以使用不同参数、不同 tokenization 方式和不同 inductive bias。
2. **训练更稳定。** 模态之间不会从第一层开始互相干扰。
3. **适合大规模检索。** 图像向量和文本向量可以提前离线缓存，检索时只需要做向量相似度搜索。
4. **扩展性强。** 可以很方便地替换 image encoder 或 text encoder。
5. **缺失模态处理更方便。** 单模态表示可以独立使用。

Late Fusion 的缺点是：

1. **跨模态交互发生得晚。** 图像 patch 和文本 token 在编码过程中通常不能细粒度互相影响。
2. **不擅长复杂推理。** 对需要逐词、逐区域、多步推理的任务，单纯向量相似度可能不够。
3. **容易只学全局语义。** dual encoder 通常更擅长“整图-整句”匹配，而不是精确定位每个词对应哪个区域。
4. **表达能力受 bottleneck 限制。** 如果每个模态最终只压成一个向量，很多细节会在融合前丢失。

> Late Fusion 更适合图文检索、零样本分类、开放词表识别等需要高吞吐和大规模候选匹配的场景；如果任务依赖细粒度跨模态推理，通常需要再加 reranker、Cross-Attention 或 multimodal encoder。

---

#### [Q11] Late Fusion 有哪些经典视觉-文本方法？

1. **⭐ CLIP：Learning Transferable Visual Models From Natural Language Supervision，2021。**

   CLIP 是最有影响力的视觉-文本 dual encoder 之一。它使用 image encoder 和 text encoder 分别把图像和文本编码成向量，然后用对比学习让匹配的 image-text pair 相似度更高，不匹配的 pair 相似度更低。

   CLIP 的关键点是：训练目标不是预测固定类别，而是学习图像和自然语言描述之间的对应关系。推理时，可以把类别名写成 prompt，例如 “a photo of a dog”，再和图像向量计算相似度，从而实现 zero-shot classification。

   从融合角度看，CLIP 几乎没有 token-level fusion：图像和文本分别编码，只在最后通过向量相似度对齐。因此它是 Late Fusion / dual encoder 的经典代表。它的优势是检索和 zero-shot 能力强、可扩展性好；缺点是细粒度推理能力不如带 Cross-Attention 的融合模型。

   > [!note] CLIP 的细节实现和作用含义
   > **模型结构：** CLIP 有两个独立 encoder：image encoder 和 text encoder。image encoder 可以是 ResNet 或 ViT，负责把图像编码成一个向量；text encoder 通常是 Transformer，负责把一句文本 prompt 编码成一个向量。两个向量会被投影到同一个 embedding space，并做归一化。
   >
     > **训练方式：** 一个 batch 中有 $N$ 个图文对，会得到 $N$ 个 image embeddings 和 $N$ 个 text embeddings。模型计算所有图像和所有文本之间的相似度，形成一个 $N\times N$ 的 similarity matrix。对角线上的 pair 是正样本，其他 $N^2-N$ 个组合是负样本。
   >
   > $$
   > s_{ij}=\frac{\langle z_i^{image},z_j^{text}\rangle}{\tau}
   > $$
   >
   > 其中 $\tau$ 是可学习或设定的 temperature，用来控制 softmax 分布的尖锐程度。训练目标通常是对称的 contrastive loss：image-to-text 方向要求每张图找回正确文本，text-to-image 方向要求每段文本找回正确图像。
   >
   > **为什么能 zero-shot：** 传统分类模型直接学习 “image → class id”，类别空间是固定的。CLIP 学的是 “image ↔ natural language description”，所以测试时可以把任意类别写成文本 prompt，例如 “a photo of a {class}”。模型比较图像向量和所有类别 prompt 向量的相似度，选择最相似的类别。
   >
   > **作用含义：** CLIP 把视觉分类问题转成了图文匹配问题，把类别标签变成了语言描述。这使模型可以利用自然语言的开放词表能力，迁移到没有专门训练过的新类别、新数据集和图文检索任务。
   >
   > **局限：** CLIP 的融合发生在全局向量层面，通常不显式建模每个 word 和每个 image patch 的细粒度对应关系。因此它很适合 retrieval、zero-shot classification 和开放词表识别，但在复杂 VQA、计数、空间关系、多步推理等任务上，往往需要额外的 Cross-Attention 或多模态 LLM 结构。

 > CLIP 的核心结构可以参考原论文 Figure 1：image encoder 和 text encoder 分别编码图像与文本，在共享 embedding space 中计算所有 image-text pair 的相似度，并用对比学习拉近匹配 pair、推远不匹配 pair。参考链接：[OpenAI CLIP Blog](https://openai.com/index/clip/)；[CLIP Paper Figure 1](https://arxiv.org/pdf/2103.00020)。

2. **ALIGN：Scaling Up Visual and Vision-Language Representation Learning With Noisy Text Supervision，2021。**

   ALIGN 和 CLIP 思路相近，也使用 image encoder + text encoder 的 dual encoder 架构，通过大规模 noisy image-text pairs 做对比学习。它的重点在于 scale：利用海量弱标注图文对，即使数据噪声较大，也能学到强大的视觉-语言对齐表示。

   ALIGN 说明了一个重要趋势：对于图文检索和开放词表识别，架构不一定要很复杂；只要 dual encoder 足够大、数据足够多、对比学习目标设计合理，就可以获得很强的迁移能力。

3. **LiT：Locked-image Tuning，2021。**

   LiT 的核心做法是锁住一个已经很强的 image encoder，只训练 text encoder 去对齐图像表示。它和从头联合训练 image encoder、text encoder 的 CLIP 不同，更强调复用已有视觉模型。

   LiT 的意义在于，它表明强视觉表征可以作为稳定锚点，语言侧去适配这个视觉空间。这对理解“冻结单模态 encoder + 学习跨模态对齐”的路线很重要，也影响了后续很多参数高效的视觉-语言训练方法。

4. **dual-encoder image-text retrieval。**

   很多图文检索系统都采用 dual encoder：图像和文本分别编码成向量，训练时用 contrastive loss，推理时用 ANN 向量检索。这类方法通常先用 Late Fusion 快速召回候选，再用 Middle / Early Fusion 的 cross-encoder 做精排。

   因此实际系统里常见两阶段设计：

   ```text
   Stage 1: dual encoder 召回大量候选，速度快
   Stage 2: cross encoder / fusion encoder 精排，交互细
   ```

### 融合机制与实践指南

#### [Q12] Cross-Attention 在多模态融合中起什么作用？

Cross-Attention 是多模态融合中最常见的机制之一。它让一个模态的 Query 去读取另一个模态的 Key 和 Value：

$$
Q = X_A W^Q,\qquad K = X_B W^K,\qquad V = X_B W^V
$$

$$
\operatorname{CrossAttn}(X_A,X_B)
=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

直观理解是：**A 模态根据自己的当前位置或语义需求，从 B 模态中检索相关信息。**

常见用法包括：

1. **文本读图像。** 文本 token 作为 Query，图像 patch 或 region 作为 Key/Value，用于视觉问答或图文理解。
2. **图像读文本。** 图像 token 作为 Query，文本 token 作为 Key/Value，用于文本引导的视觉表示。
3. **latent tokens 读多模态输入。** 少量 learned latent tokens 通过 Cross-Attention 从大量输入 token 中抽取信息，降低后续 Self-Attention 成本。

Cross-Attention 和直接拼接 Self-Attention 的区别是：

| 方法 | Query 来源 | Key/Value 来源 | 特点 |
| --- | --- | --- | --- |
| 拼接后 Self-Attention | 所有模态 | 所有模态 | 交互最自由，但成本较高 |
| Cross-Attention | 一个模态或 latent | 另一个模态或多模态 memory | 方向更明确，计算更可控 |

#### [Q13] Gating 在多模态融合中有什么作用？

Gating 指让模型动态控制不同模态或不同融合分支的权重。简单形式可以写成：

$$
g=\sigma(W[z_A,z_B])
$$

$$
z=g\odot z_A+(1-g)\odot z_B
$$

其中 $g$ 是一个取值在 $0$ 到 $1$ 之间的门控权重。它的作用是：

1. **动态选择信息来源。** 不同样本、不同位置可以依赖不同模态。
2. **抑制噪声模态。** 如果某个模态质量较差，门控可以降低它的影响。
3. **缓解模态冲突。** 当两个模态给出矛盾证据时，模型可以学习更可信的来源。
4. **增强可解释性。** 门控权重可以作为粗略信号，观察模型在不同情况下更依赖哪些模态。

Gating 不一定替代 Attention。实践中常见做法是先用 Cross-Attention 产生候选融合表示，再用 gate 控制原始表示和融合表示的比例。

#### [Q14] 三种融合方式应该如何选择？

可以按照模态差异、任务依赖和计算成本来选择：

| 选择条件 | 更适合的方法 | 原因 |
| --- | --- | --- |
| 输入长度可控，需要细粒度跨模态交互 | Early Fusion | 直接拼接 token，交互最充分 |
| 需要词-区域或词-patch 级别理解 | Early / Middle Fusion | Self-Attention 或 Cross-Attention 可以建模细粒度关系 |
| 模态差异大，但任务依赖中层跨模态交互 | Middle Fusion | 兼顾 modality-specific pattern 和 cross-modal dependency |
| 希望复用成熟单模态预训练模型 | Middle / Late Fusion | 可以保留各自 encoder，再增加融合层或对齐目标 |
| 需要大规模图文检索或 zero-shot 分类 | Late Fusion | dual encoder 可以离线缓存向量，推理效率高 |
| 数据量较小，担心模态互相污染 | Middle / Late Fusion | 显式分离低层表示，训练更稳 |
| 输入 token 很多，Attention 成本敏感 | Middle / Late Fusion / latent bottleneck | 避免一开始把所有 token 拼成超长序列 |

简化地说：

- **Early Fusion：** 简单、强交互，代表是 VisualBERT、VL-BERT、UNITER、ViLT；适合理解细节，但成本高。
- **Middle Fusion：** 先单模态建模，再跨模态交互，代表是 ViLBERT、LXMERT、ALBEF、BLIP、BLIP-2；是理解与生成任务中常见折中。
- **Late Fusion：** 先独立编码，最后对齐或打分，代表是 CLIP、ALIGN、LiT；适合检索和 zero-shot，但细粒度推理较弱。

#### [Q15] 多模态融合中常见的问题有哪些？

1. **模态缺失。** 训练或推理时某些模态不可用，需要模态 dropout、missing embedding 或 fallback encoder。
2. **模态噪声。** 某个模态可能质量较差，例如图像模糊、文本不完整或图文不匹配。
3. **模态不平衡。** 一个模态信息量更大、token 更多或更容易优化，导致模型忽略其他模态。
4. **负迁移。** 加入额外模态后，如果噪声或冲突过强，性能反而下降。
5. **对齐困难。** 不同模态的语义粒度、长度和结构不同，不一定天然一一对应。
6. **计算成本高。** 多模态输入通常 token 数更多，尤其是图像 patch、音频帧或视频帧。
7. **评估复杂。** 需要区分模型是真的利用了多模态信息，还是只依赖单一模态捷径。

常见缓解方法包括：模态 dropout、门控融合、对比学习预对齐、冻结部分 encoder、平衡采样、loss reweighting 和更细的 ablation study。
