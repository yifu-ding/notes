### 在线学习

#### [Q1] 什么是 Online Learning？

Online Learning（在线学习）是指模型随着数据流持续到达，不断利用新样本更新参数，而不是等待收集完整数据集后再统一训练。

对于第 $t$ 个样本 $(x_t,y_t)$，模型先使用当前参数进行预测，再根据真实标签更新参数：

$$
\hat y_t=f_{\theta_t}(x_t)
$$

$$
\theta_{t+1}
=
\theta_t-\eta_t\nabla_{\theta_t}
\ell\left(f_{\theta_t}(x_t),y_t\right)
$$

这一过程也称为 **predict-then-update**。Online Learning 适合推荐系统、广告点击率预测、金融数据流等数据分布不断变化的场景。它的优势是更新及时、无需反复保存完整数据集，但也更容易受到噪声样本、数据投毒和灾难性遗忘的影响。

需要注意，==Online Learning 不等于 Online Inference==。一个模型即使实时响应请求，只要参数没有根据新数据持续更新，仍然只是在线推理。

> [!tip]
> **Online Learning ≠ Online Inference**：前者要求参数随新数据持续更新；后者只是实时响应请求，参数不变。两者容易混淆。

---

#### [Q2] Online Learning 是否需要在 Serving 时直接更新参数？

不一定。严格的同步在线学习会让 Serving 模型在每次预测并获得反馈后立即更新参数，但反向传播会增加延迟，并可能引发并发读写冲突和模型不稳定。

生产环境通常采用异步架构：Serving 服务负责推理和收集反馈，独立训练服务使用新数据更新候选模型；候选模型通过离线评测和安全检查后，再部署到线上。因此，**模型持续更新不等于 Serving 实例边推理边反向传播**。

如果系统每隔数小时或每天汇总新数据、重新训练并部署，通常称为 **Nearline Learning**。它的更新频率低于严格的 Online Learning，但工程上更稳定，也更常见。

> [!tip]
> 生产系统更常见的是**异步架构**（Serving 与训练解耦）或 **Nearline Learning**（定期汇总更新、评测通过后上线），而非边推理边反向传播的严格同步 Online Learning。

---

#### [Q3] LLM 如何实现低成本 Online Learning？

LLM 的全参数在线更新成本很高，实际系统通常冻结基础模型，只更新 LoRA、Adapter 或最后几层。以 LoRA 为例：

$$
W=W_0+BA
$$

其中基础权重 $W_0$ 固定，只训练低秩矩阵 $A$ 和 $B$。这样可以减少反向传播、优化器状态和参数同步开销，同时降低灾难性遗忘的风险。

训练侧通常使用 BF16、mini-batch 和 replay buffer。Mini-batch 可以减少更新频率，replay buffer 则通过混入代表性的历史样本，避免模型只适应最新数据而忘记旧知识。Serving 侧可以使用 INT8 或 INT4 量化，但一般应保留一份高精度训练权重，因为极低精度参数不适合频繁更新。

因此，较常见的方案是：异步收集反馈，使用 LoRA 持续训练，加入历史数据防止遗忘，验证通过后再量化并更新 Serving 模型。

> [!tip] LLM Online Learning 推荐方案
> 冻结 $W_0$ → 只训练 **LoRA** 低秩矩阵 → **mini-batch + replay buffer** 防遗忘 → 异步评测 → 量化后更新 Serving 模型。

### 上下文学习

#### [Q4] 什么是 In-Context Learning？

In-Context Learning（ICL，上下文学习）是指模型在**不更新参数**的情况下，根据当前上下文中的任务描述和输入输出示例，临时推断任务规律并完成新输入。

> 例如，Prompt 中先给出“电影很好 → positive”和“剧情无聊 → negative”，再输入“演员表现令人惊喜”。模型可以从前两个示例中推断当前任务是情感分类、输出标签为 `positive/negative`，最终回答 `positive`。

形式化地，给定上下文示例 $\mathcal D_{\text{context}}=\{(x_i,y_i)\}_{i=1}^{k}$，模型预测：

$$
\hat y
=
\arg\max_y
p_\theta
\left(y\mid\mathcal D_{\text{context}},x\right)
$$

推理前后参数保持不变：

$$
\theta_{\mathrm{after}}=\theta_{\mathrm{before}}
$$

因此，ICL 中的”学习”并不是把新知识写入权重，而是在当前前向传播中形成临时的任务表示。==上下文消失后，这种适应通常也随之消失。==

---

#### [Q5] Zero-shot、One-shot 和 Few-shot 有什么区别？

| 设置 | 示例数量 | 说明 |
| --- | ---: | --- |
| Zero-shot | 0 | 只提供任务指令，依赖模型已有知识完成任务 |
| One-shot | 1 | 提供一个输入输出示例 |
| Few-shot | 少量 | 提供多个示例，让模型归纳任务和输出格式 |

Few-shot 示例不仅可以告诉模型“任务是什么”，还会隐式规定标签空间、回答格式和语言风格。例如，分类任务中的示例可以规定输出 `A/B` 而不是自然语言，抽取任务中的示例可以规定输出 JSON。

示例并不是越多越好。错误示例、类别失衡或无关示例会误导模型；过多示例还会增加 Prefill 成本并占用上下文窗口。

---

#### [Q6] ICL 与 Fine-tuning 的本质区别是什么？

| 维度 | In-Context Learning | Fine-tuning |
| --- | --- | --- |
| 参数是否更新 | 不更新 | 更新全部或部分参数 |
| 适应位置 | 上下文和隐藏状态 | 模型权重 |
| 持续时间 | 当前上下文内有效 | 保存参数后长期有效 |
| 计算方式 | 只执行前向传播 | 需要反向传播 |
| 任务切换 | 更换 Prompt | 更换模型或 Adapter |
| 主要问题 | 对示例和顺序敏感 | 训练成本和灾难性遗忘 |

两者可以表示为：

$$
\text{ICL:}\quad
\hat y=f_\theta(\mathcal D_{\text{context}},x),
\qquad \theta\text{ 固定}
$$

$$
\text{Fine-tuning:}\quad
\theta'
=
\theta-\eta\nabla_\theta\mathcal L(\mathcal D_{\text{train}}),
\qquad
\hat y=f_{\theta'}(x)
$$

==任务频繁变化、训练样本很少时，ICL 更灵活；任务长期稳定、调用量较大并且要求输出一致时，Fine-tuning 通常更合适。== LoRA 和 Prompt Tuning 虽然只训练少量参数，但仍发生了参数优化，因此属于参数高效微调，而不是 ICL。

#### [Q7] ICL 没有更新参数，为什么仍然能学习新任务？

ICL 能力主要来自预训练。模型在大规模文本中见过问答、翻译、分类、类比以及“示例后接答案”等模式，因此学会了根据上下文识别任务，并继续其中的输入输出规律。

一种直观解释是，模型参数保存了跨任务的知识和学习策略，Prompt 中的示例则帮助模型判断本次应该调用哪种策略。Transformer 的 Attention 可以在上下文中建立 $x_i$ 与 $y_i$ 的对应关系，再将这种关系应用到新的输入 $x$：

$$
\{(x_1,y_1),\ldots,(x_k,y_k)\}
\longrightarrow
g_{\mathcal D}(x)
$$

从 Meta-learning 的角度看，预训练相当于让模型“学会如何从示例中学习”；从贝叶斯视角看，模型根据示例更新了对当前潜在任务的判断。这些解释并不矛盾，但目前没有一个机制能够完整解释所有模型和任务中的 ICL 现象。

> [!note]
> 有些研究将 ICL 解释为 Transformer 在隐藏状态中近似执行梯度下降。这是一种理论解释，不应表述为所有 ICL 都严格等价于梯度更新。

---

#### [Q8] ICL 没有更新模型参数，为什么说它可能在“近似执行梯度下降”？

这里的“近似执行梯度下降”不是指 Transformer 真的修改了自身参数 $\theta$，而是指它的前向传播过程可以实现一个与梯度下降相似的**计算过程**。

假设上下文中的示例来自一个简单的线性任务：

$$
y_i=w^\top x_i
$$

如果使用普通梯度下降学习这个任务，需要先初始化一个临时参数 $w_0$，再根据示例计算预测误差并更新：

$$
w_{t+1}
=
w_t-\eta
\sum_i
(w_t^\top x_i-y_i)x_i
$$

最后使用更新后的 $w_t$ 预测新输入 $x$。传统训练会把 $w_t$ 存储为可更新的模型参数，而 ICL 中没有这样一个被优化器直接更新的参数。

但是，Transformer 可以利用 Attention 读取上下文中的 $(x_i,y_i)$，计算输入之间的相关性和预测残差，再把这些信息写入当前 Token 的隐藏状态。随着网络层数增加，隐藏状态可以逐层变化，其计算结果可能近似于：

$$
h^{(0)}
\rightarrow
h^{(1)}
\rightarrow
\cdots
\rightarrow
h^{(L)}
$$

$$
h^{(l+1)}
\approx
h^{(l)}-\eta\nabla_h\mathcal L
$$

这里变化的是中间激活 $h$，而不是模型参数 $\theta$。可以把 $h$ 理解为模型在本次 Prompt 内部构造的“临时任务参数”或“临时预测器”。Prompt 结束后，这些隐藏状态被清除，因此不会形成持久学习。

一个直观类比是：计算器的硬件没有因为计算 $2+3$ 而改变，但固定的硬件电路可以执行加法算法。类似地，Transformer 的权重没有变化，但固定的 Attention 和 FFN 可以在一次前向传播中执行类似“计算误差—修正临时预测器—完成预测”的算法。

因此需要区分两种更新：

| 更新对象 | 是否发生 | 说明 |
| --- | --- | --- |
| 模型参数 $\theta$ | 否 | Transformer 的权重保持不变 |
| 隐藏状态或临时任务表示 $h$ | 是 | 随上下文和网络层逐步变化 |

> [!important]
> “近似梯度下降”描述的是前向传播所实现的算法，而不是训练框架真的调用了 `backward()` 或优化器。相关理论通常在专门构造的线性回归等任务上证明或观察到这种对应关系，不能直接断言所有真实 LLM 的 ICL 都通过这一机制完成。

#### [Q9] 哪些因素会影响 ICL 的效果？

**ICL 对示例的正确性、相关性、覆盖范围和排列顺序都很敏感。** 与当前 Query 语义相近、格式统一并且能够覆盖主要类别的示例通常效果更好；错误标签和类别不平衡则可能产生明显偏置。

当候选示例很多时，可以使用 Embedding 检索与当前 Query 最相似的 $k$ 个示例：

$$
\mathcal D_k(x)
=
\operatorname{TopK}_{(x_i,y_i)\in\mathcal D}
\operatorname{sim}\left(e(x),e(x_i)\right)
$$

示例顺序同样会影响结果。模型通常更容易利用**靠近上下文开头和结尾**的信息，而可能忽略中间内容，即 **Lost in the Middle**。因此，==关键指令和最相关示例通常应放在更显著的位置==，并在验证集上测试不同的示例组合，而不能假设示例顺序无关。

#### [Q10] ICL 的主要优点和局限是什么？

ICL 最大的优点是不需要训练新的模型，只需修改 Prompt 就能快速切换任务。它尤其适合样本很少、需求经常变化，或者需要临时指定标签和输出格式的场景。

它的局限也比较明显。首先，示例会占用上下文窗口并增加 Prefill 延迟；其次，结果对 Prompt 措辞、示例选择和排列顺序敏感，稳定性通常弱于经过充分训练的专用模型。此外，ICL 不会持久保存新知识，错误示例和 Prompt Injection 也可能直接改变模型行为。

ICL 的效果还受到模型能力上限的约束。如果一个任务远离预训练分布，或者需要模型从少量示例中掌握全新的复杂算法，仅靠 ICL 通常不够。

#### [Q11] ICL、Prompt Engineering、Prompt Tuning 和 RAG 有什么区别？

| 概念 | 是否训练参数 | 核心作用 |
| --- | --- | --- |
| Prompt Engineering | 否 | 设计自然语言指令、结构和示例 |
| In-Context Learning | 否 | 根据上下文临时推断任务规律 |
| Prompt Tuning | 是 | 训练一组连续的 Soft Prompt 向量 |
| RAG | 通常否 | 从外部知识库检索事实并放入上下文 |

Prompt Engineering 是构造输入的方法，ICL 是模型利用这些输入进行临时适应的能力。Few-shot Prompt 是最典型的 ICL 形式，但两者并不完全等价。

RAG 和 ICL 都通过上下文影响输出，但作用不同：==ICL 主要告诉模型「任务应该怎么做」，RAG 主要告诉模型「回答需要使用哪些知识」==。二者可以结合，例如使用 Few-shot 示例规定引用格式，再使用检索文档提供事实依据。

Prompt Tuning 名称中虽然包含 Prompt，但它需要训练 Soft Prompt 参数，因此本质上属于 PEFT。[[#[Q12] Prompt Tuning 如何训练 Soft Prompt？]]

### Prompt Tuning

#### [Q12] Prompt Tuning 如何训练 Soft Prompt？

Prompt Tuning 冻结预训练模型的全部参数，只训练一小组连续向量。这些向量不对应词表中的真实 Token，因此称为 **Soft Prompt** 或 Virtual Token。

假设 Soft Prompt 包含 $m$ 个向量，每个向量的维度与模型的词嵌入维度 $d$ 相同：

$$
P=[p_1,p_2,\ldots,p_m]\in\mathbb R^{m\times d}
$$

对于输入 Token $x_1,\ldots,x_n$，先通过冻结的 Embedding Layer 得到：

$$
X=[e(x_1),e(x_2),\ldots,e(x_n)]
$$

然后将 Soft Prompt **拼接**到输入 Embedding **前面**：

$$
H_0=[P;X]
$$

Soft Prompt 的作用可以理解为：**在不修改模型权重的情况下，为后续 Token 提供一组可学习的上下文信号。** 对 Transformer 来说，Soft Prompt 和普通 Token Embedding 都只是 $d$ 维向量。进入模型后，它们同样会被投影为 Key 和 Value：

$$
K_P=PW_K,\qquad V_P=PW_V
$$

当后续真实 Token 计算 Self-Attention 时，可以关注 Soft Prompt 对应的 Key，并将其 Value 信息混入自己的表示：

$$
h_i'
=
\sum_j
\operatorname{softmax}
\left(
\frac{q_i k_j^\top}{\sqrt d}
\right)v_j
$$

这里的 $j$ 不仅包括真实 Token，也包括前面的 Soft Prompt。因此，改变 $P$ 就会改变 Soft Prompt 产生的 $K_P$ 和 $V_P$，进而改变后续 Token 的 Attention 权重和隐藏状态。这种影响还会经过多层 Attention 和 FFN 继续传播，最终改变输出概率。

> 例如，在情感分类任务中，随机初始化的 Soft Prompt 一开始没有明确作用。如果模型把正面评论预测成错误标签，Loss 的梯度会沿输出层和 Transformer 各层传回 $P$，调整这些向量。经过大量样本训练后，Soft Prompt 会形成一种稳定的激活模式，使模型更容易调用预训练中已经学到的情感判断能力，并按照指定标签输出。

因此，Soft Prompt 通常不是向模型写入大量新知识，而更像一个**可训练的任务控制信号**：它引导冻结模型重点调用哪些已有能力、关注哪些信息，以及采用什么输出格式。

拼接后的序列正常经过 Transformer。训练时仍使用任务对应的监督损失，例如生成任务使用交叉熵：

$$
\mathcal L
=
-
\sum_t
\log p_{\theta,P}(y_t\mid x,y_{<t})
$$

反向传播会穿过整个 Transformer 来计算梯度，但基础模型参数 $\theta$ 被设置为冻结状态，优化器只更新 Soft Prompt：

$$
P
\leftarrow
P-\eta\nabla_P\mathcal L,
\qquad
\theta\text{ 保持不变}
$$

因此，“经过模型反向传播”和“更新模型权重”不是一回事。Transformer 仍参与梯度计算，因为需要知道每个 Soft Prompt 向量应如何变化；但最终只有 $P$ 会被优化器修改。

Soft Prompt 可以随机初始化，也可以使用真实词的 Embedding 初始化。训练完成后，每个任务只需保存一个很小的 Prompt 矩阵。推理时将对应的 Soft Prompt 拼接到输入前面，不再执行反向传播。

| 方法 | 可训练参数的位置 | 特点 |
| --- | --- | --- |
| Prompt Tuning | 仅输入层前的 Soft Prompt | 参数最少，但小模型上能力可能有限 |
| Prefix Tuning | Transformer 每层 Attention 的 Prefix KV | 对生成任务控制更强 |
| P-Tuning v2 | 每层加入可训练 Prompt | 也称 Deep Prompt Tuning |
| LoRA | Attention 或 FFN 权重旁的低秩矩阵 | 参数更多，但通常更加稳定和通用 |

Prompt Tuning 学到的不是人类可读的自然语言指令，而是一组对当前任务有效的连续向量。所谓“将隐藏状态引导到目标任务区域”，并不是模型内部预先存在一个边界明确的区域，而是一种直观描述：加入 Soft Prompt 后，输入经过 Transformer 得到的隐藏表示，更容易被输出层映射成目标任务要求的答案。

例如，同一句评论在没有 Soft Prompt 时可能被模型当作普通续写；加入训练好的情感分类 Soft Prompt 后，其隐藏状态会更有利于输出 `positive/negative`。Soft Prompt 改变的是模型处理输入时的计算路径，而不是输入文本本身，也不是基础模型参数。

> [!summary] Prompt Tuning 核心要点
> 1. **冻结基础模型** $\theta$，只训练 Soft Prompt 矩阵 $P \in \mathbb{R}^{m \times d}$
> 2. $P$ 拼接在输入 Embedding 前，通过 Attention 的 K/V 影响后续 Token 的表示
> 3. 反向传播穿过完整 Transformer，但优化器==只更新 $P$，不更新 $\theta$==
> 4. 每个任务只需保存一个小矩阵；小模型效果通常弱于 LoRA，大模型（≥11B）上差距缩小

### Continual Learning

#### [Q13] Continual Learning 与 Online Learning 有什么区别？

Online Learning 强调数据以流式方式到达，模型需要及时预测并更新；Continual Learning 强调模型长期学习新的任务或分布，同时尽量保留旧知识。

| 维度 | Online Learning | Continual Learning |
| --- | --- | --- |
| 核心问题 | 如何及时适应数据流 | 如何学习新知识而不忘旧知识 |
| 数据形式 | 样本或 Mini-batch 顺序到达 | Task、Domain 或 Class 分阶段变化 |
| 主要指标 | Online Loss、Regret、适应速度 | 新任务性能和遗忘程度 |
| 是否要求实时 | 通常强调 | 不一定 |

Online Learning 常使用 Regret 衡量在线策略与最佳固定策略之间的累计差距：

$$
R_T
=
\sum_{t=1}^{T}\ell_t(\theta_t)
-
\min_\theta\sum_{t=1}^{T}\ell_t(\theta)
$$

Continual Learning 则更关注灾难性遗忘，常通过历史数据回放、正则化、知识蒸馏或为不同任务分配独立参数空间来缓解。一个持续接收用户反馈并更新的推荐系统，既可能属于 Online Learning，也可能同时面临 Continual Learning 问题。

> [!tip]
> ==Online Learning 关注**实时性**，Continual Learning 关注**不遗忘**==。二者可以同时出现在同一个系统中。

---


#### [Q16] Continual Learning 有哪些代表性技术和工作？

Continual Learning 的核心矛盾是 **stability-plasticity dilemma**：模型既要具有足够的可塑性来学习新任务，又要保持足够的稳定性，避免覆盖旧任务知识。代表性方法通常分为以下几类：

| 技术路线 | 核心思路 | 代表工作 |
| --- | --- | --- |
| 正则化方法 | 限制重要参数或旧模型输出发生过大变化 | LwF、EWC |
| Replay 方法 | 学习新任务时混入少量历史样本 | Experience Replay、GEM、iCaRL |
| Generative Replay | 使用生成模型重建旧任务数据 | Deep Generative Replay |
| 参数隔离 | 为不同任务分配独立参数或子网络 | Progressive Neural Networks、PackNet |

**LwF（Learning without Forgetting，2016）**不保存旧数据，而是使用旧模型对新数据产生 soft target，再通过知识蒸馏约束新模型保持原有输出。它实现简单，但当新旧任务分布差异较大时，仅依靠新数据上的蒸馏可能不足以保留旧知识。

**EWC（Elastic Weight Consolidation，2017）**使用 Fisher Information 衡量各参数对旧任务的重要性，并惩罚重要参数偏离旧值：

$$
\mathcal L
=
\mathcal L_{\mathrm{new}}
+
\frac{\lambda}{2}
\sum_i
F_i(\theta_i-\theta_i^*)^2
$$

其中 $F_i$ 越大，表示参数 $\theta_i$ 对旧任务越重要，学习新任务时越不应大幅修改。

> [!question] Fisher 信息具体怎么算？它为什么能反映参数的"重要性"？
> **定义**：Fisher Information 衡量的是"模型输出的对数似然，对参数 $\theta_i$ 有多敏感"，标准定义是对数似然梯度的平方的期望（对数据分布取期望）：
>
> $$
> F_i = \mathbb{E}_{x\sim\mathcal D_{\text{old}}}\left[\left(\frac{\partial \log p(y\mid x;\theta)}{\partial \theta_i}\right)^2\right]
> $$
>
> 实践中（包括原始 EWC 论文）通常用**旧任务训练好的模型 $\theta^*$**，在旧任务数据（或其子集）上跑一遍前向+反向，把每个参数的梯度逐样本平方后取平均，作为 $F_i$ 的**经验估计**——这其实就是损失对参数的**对角 Fisher 近似**，不需要算二阶导数（真正的 Fisher 信息等价于负对数似然 Hessian 的期望，但直接算 Hessian 代价太高，所以用"梯度平方的期望"这一等价、且只需一阶梯度的形式）。
>
> **为什么梯度平方大就代表"重要"**：
> - 如果在旧任务最优点 $\theta^*$ 附近，损失函数对 $\theta_i$ 的梯度**普遍较大**（在不同样本上都不小），说明哪怕 $\theta_i$ 只发生很小的扰动，旧任务的损失也会显著上升——这个参数对"维持旧任务表现"是**敏感且关键**的，必须重点保护。
> - 反之，如果损失对 $\theta_i$ 的梯度普遍接近 0（损失曲面在这个方向很"平"），说明改变 $\theta_i$ 几乎不影响旧任务效果——这种参数可以**自由地**被新任务重新利用，不需要施加惩罚。
> - 直觉上可以类比成"损失曲面在 $\theta_i$ 方向的曲率/陡峭程度"：$F_i$ 大 ≈ 这个方向曲率大、损失曲面陡，稍微挪动就会摔出旧任务的"舒适区"；$F_i$ 小 ≈ 这个方向曲面平坦，挪动的代价很低。
>
> **加入损失函数后的效果**：把 $F_i(\theta_i-\theta_i^*)^2$ 当作正则项加进新任务的 loss，相当于给每个参数一个**单独的、与其重要性成正比的"弹簧"**——重要参数（$F_i$ 大）的弹簧硬，稍微偏离 $\theta_i^*$ 就会受到很大惩罚，新任务的梯度很难把它拉走；不重要的参数（$F_i$ 小）弹簧软，几乎不受约束，可以自由地被新任务训练改变，这正是 EWC 名字里"Elastic（弹性）"的来源。
>
> **局限**：实践中常用的是**对角近似**（只算每个参数自己的 $F_i$，忽略参数间的协方差/相关性），计算上简单但不完全精确；真正的 Fisher 信息矩阵是满秩的，包含参数之间的相互影响，对角近似相当于假设各参数的重要性互相独立。

**GEM（Gradient Episodic Memory，2017）**保存少量旧样本，并约束新任务梯度不能增加旧任务损失。**iCaRL（2017）**则维护每个旧类别的代表性样本，并结合蒸馏与最近类均值分类器，成为 Class-Incremental Learning 的经典方法。

实践中 Replay 通常比单纯正则化更稳定，但需要保存历史数据；参数隔离可以有效避免干扰，却会使模型容量随任务数量增长。LLM 场景中常见的思路是历史数据回放、知识蒸馏，以及为不同任务维护独立 LoRA 或 Adapter。

> [!tip] LLM 场景实践
> ==Replay（历史数据混入）通常优于纯正则化==。推荐方案：**历史 Replay + 独立 LoRA/Adapter + 知识蒸馏**三者结合使用。

### Test-Time Adaptation、Test-Time Training

#### [Q14] 什么是 Test-Time Adaptation、Test-Time Training 

Test-Time Adaptation（TTA）是指模型在测试或部署阶段，利用目标域的无标签数据、伪标签或统计量变化来适应新的数据分布。它可能更新 BatchNorm 统计量，也可能更新部分参数。

Test-Time Training（TTT）通常被视为 TTA 的一种形式。模型针对当前测试样本，通过自监督辅助目标执行梯度更新：

$$
\theta_x'
=
\theta-\eta\nabla_\theta\mathcal L_{\mathrm{aux}}(x)
$$

| 方法 | 是否反向传播 | 适应信号 |
| --- | --- | --- |
| ICL | 否 | Prompt 中的指令和示例 |
| TTA | 可能 | 测试分布、无标签数据或伪标签 |
| TTT | 是 | 当前测试样本上的辅助 Loss |

因此，==ICL 虽然也发生在推理阶段，但它不修改参数，不能因为发生在 Test Time 就归类为 TTT==。类似地，Inference-time Scaling 通过增加采样、搜索或验证提高效果，通常也不属于 TTT。

> [!tip] 三者区分
> - **ICL**：前向传播，参数不变，适应在隐藏状态中临时发生
> - **TTA**：可能更新 BN 统计量或部分参数，不需要标注标签
> - **TTT**：对当前测试样本用辅助目标做反向传播，参数有更新

---

#### [Q17] Test-Time Adaptation 有哪些代表性技术和工作？

Test-Time Adaptation ==通常假设无法访问源训练数据和目标域标签，只能利用测试数据本身调整模型。==常见技术包括更新归一化统计量、熵最小化、自监督学习、伪标签和 Teacher-Student 一致性训练。

| 代表工作 | 核心方法 | 是否反向传播 |
| --- | --- | --- |
| AdaBN（2016） | 使用目标域数据重新估计 BatchNorm 统计量 | 否 |
| TTT（2020） | 通过旋转预测等自监督辅助任务更新模型 | 是 |
| TENT（2021） | 最小化预测熵，只更新归一化层参数 | 是 |
| T3A（2021） | 根据测试样本动态调整分类器原型 | 否 |
| CoTTA（2022） | Teacher-Student、增强平均与随机参数恢复 | 是 |
| EATA（2022） | 筛选可靠样本，并用 Fisher 正则减少遗忘 | 是 |
| SAR（2023） | 过滤不可靠样本并使用 Sharpness-Aware 优化 | 是 |

**TENT** 是最经典的 Fully Test-Time Adaptation 方法。它==通过最小化测试样本预测分布的熵，使模型在目标域上产生更确定的预测==：

$$
\mathcal L_{\mathrm{TENT}}
=
-
\sum_c
p_\theta(y=c\mid x)
\log p_\theta(y=c\mid x)
$$

为了降低风险，TENT 通常只更新 BatchNorm 的 affine 参数，而不更新整个模型。它的主要问题是：错误但高置信度的预测也会被继续强化，从而产生 confirmation bias。

**CoTTA** 面向持续变化的测试分布，使用指数移动平均 Teacher 提供稳定目标，并通过随机恢复部分源模型参数缓解错误累积。**EATA** 和 **SAR** 进一步筛除高熵或不可靠样本，避免每个测试样本都参与更新。

TTA 的关键不是“更新越多越好”，而是在适应目标分布和保持原模型能力之间取得平衡。实际应用还需要考虑小 Batch、类别分布不均、样本相关性和在线反向传播带来的延迟。

### Meta-learning 

#### [Q15] 什么是 Meta-learning 

Meta-learning（元学习）通常被概括为 **Learning to Learn**：模型在多个任务上训练，目标不是只记住某个任务，而是获得快速适应新任务的能力。

经典 Meta-learning 会将每个任务的数据划分为 Support Set 和 Query Set。模型先使用 Support Set 适应任务，再通过 Query Set 评价适应效果。以 MAML 为例，其内循环更新为：

$$
\theta_i'
=
\theta-\alpha\nabla_\theta
\mathcal L_{\mathcal T_i}^{\mathrm{support}}(\theta)
$$

ICL 可以看作一种不显式更新参数的 Meta-learning 行为：上下文示例类似 Support Set，待回答的问题类似 Query Set，而适应过程发生在 Transformer 的隐藏状态和 Attention 计算中。

但二者并不等价。Meta-learning 是一种训练范式，可以通过梯度更新、记忆网络或 Learned Optimizer 实现；ICL 则是推理阶段表现出的上下文适应能力，并不要求模型接受过显式的 Meta-learning 训练。

> [!summary]
> **ICL 改变上下文，不改变参数；Online Learning 随数据流持续改变参数；Continual Learning 关注更新参数时如何避免遗忘；TTA/TTT 在测试阶段调整模型；Meta-learning 学习的是快速适应新任务的方法。**


---

#### [Q18] Meta-learning 有哪些代表性技术和工作？

Meta-learning 的方法通常分为 Metric-based、Optimization-based 和 Model-based 三类。

| 技术路线 | 核心思路 | 代表工作 |
| --- | --- | --- |
| Metric-based | 学习一个适合 Few-shot 分类的特征与距离空间 | Matching Networks、Prototypical Networks、Relation Networks |
| Optimization-based | 学习容易被少量梯度步骤快速适应的初始化或优化规则 | MAML、Meta-SGD、Reptile |
| Model-based | 使用记忆网络或 Meta Network 直接产生任务相关状态或参数 | MANN、Meta Networks |

**Matching Networks（2016）**将 Query 与 Support Set 中的样本进行 Attention 匹配，并根据相似度加权预测标签。**Prototypical Networks（2017）**进一步为每个类别计算一个原型，即该类 Support Embedding 的均值：

$$
c_k
=
\frac{1}{|S_k|}
\sum_{(x_i,y_i)\in S_k}
f_\theta(x_i)
$$

Query 根据其与各类别原型的距离完成分类。该方法结构简单，是 Few-shot Classification 中最经典的基线之一。

**MAML（2017）**属于 Optimization-based Meta-learning。它寻找一个良好的参数初始化，使模型在新任务上只需少量梯度更新就能取得较好效果。**Reptile（2018）**使用一阶近似避免计算高阶梯度，训练成本低于标准 MAML。

Model-based 方法则显式引入记忆或参数生成机制。例如 **Memory-Augmented Neural Networks（2016）**使用外部记忆快速绑定样本与标签，**Meta Networks（2017）**使用 Meta Learner 根据当前任务生成 Fast Weights。

Metric-based 方法通常适合分类任务；Optimization-based 方法更加通用，但双层优化成本较高；Model-based 方法适应速度快，但架构设计和训练稳定性更复杂。
