### 扩散语言模型基本概念

#### [Q1] 什么是 Diffusion Language Model？它和自回归 LLM 的核心区别是什么？

**Diffusion Language Model（DLM）** 可以理解为把扩散模型的“逐步去噪”思想搬到离散文本生成上。自回归 LLM 生成的是一个从左到右的条件分解：$p(x)=\prod_{t=1}^{n}p(x_t\mid x_{<t})$。它每一步只预测当前位置的下一个 token。

DLM 则通常从一个含有大量 `[MASK]` 的完整序列开始，然后经过多轮迭代，把未知位置逐渐恢复成具体 token：$z^{(T)}\rightarrow z^{(T-1)}\rightarrow \cdots \rightarrow z^{(0)}$。这里的 $z^{(T)}$ 可以是“Prompt + 一段 `[MASK]`”，$z^{(0)}$ 是最终文本。DLM 的关键不是“向右追加”，而是**在完整序列上反复修正未知位置**。因此它天然更接近 BERT 式的双向建模，也更容易做并行预测。

> [!note] 面试里最核心的一句话
> **AR 模型是 left-to-right generation，DLM 是 iterative denoising / iterative unmasking。** 前者每步生成一个新 token，后者每步可以同时预测多个未知位置。

两者的注意力结构也不同。AR 模型通常使用 causal attention，当前位置不能看未来；DLM 通常使用 bidirectional attention，每个位置都能看全局上下文。这使 DLM 在填空、编辑、非左到右生成上更自然，但也让推理缓存和工程加速更困难。

#### [Q2] DLM 的训练目标是什么？为什么常和 Masked LM 联系在一起？

DLM 在文本上的常见做法是 **masked diffusion**：正向过程不断把真实 token 替换成 `[MASK]` 或噪声 token，反向过程学习从被破坏的序列中恢复原文。若 $\mathcal M$ 表示被 mask 的位置，训练目标可以写成 $\max_\theta \log p_\theta(x_{\mathcal M}\mid x_{\overline{\mathcal M}})$。

也就是给定未被 mask 的 token，预测所有被 mask 的 token。实际训练中通常对被 mask 位置做交叉熵损失：$\mathcal L=-\sum_{i\in\mathcal M}\log p_\theta(x_i\mid z)$。

这和 BERT 的 Masked Language Modeling 很像，但目标不完全一样。BERT 主要是为了学一个强表征模型；DLM 的目标是把这种 mask 预测机制组织成一个**可迭代生成的反向去噪过程**。也就是说，DLM 不只是“做完形填空”，而是要通过多步 unmask 从噪声序列生成完整答案。

==可以把 DLM 理解为：用 Masked LM 的形式训练，用 Diffusion 的方式采样。==

#### [Q3] DLM 推理时的“下一个 token”是怎么产生的？

DLM 一般没有 AR 意义上的唯一“下一个 token”。AR 模型生成的是 $p(x_{t+1}\mid x_{\le t})$，必须先生成 $x_t$，才能生成 $x_{t+1}$。DLM 更像是在当前“部分已知、部分未知”的完整序列上，同时预测所有未知位置：$p_\theta(x_{\mathcal M}\mid x_{\overline{\mathcal M}})$。

例如当前序列是 $[\texttt{The},\texttt{[MASK]},\texttt{[MASK]},\texttt{[MASK]}]$，一次 forward 会同时给所有 `[MASK]` 位置输出词表分布。位置 2 可能最像 `cat`，位置 4 可能最像 `mat`，每个位置都有自己的 logits。随后解码策略再决定本轮哪些位置正式提交，哪些位置继续保持 `[MASK]`。

最保守的策略是每轮只提交一个最有信心的位置，形式上可以写成 $i^*=\arg\max_{i\in\mathcal M}\max_v p_\theta(v\mid z)$。但这个位置不一定是最左边的 `[MASK]`，下一轮也不一定填它右边的位置。DLM 可以先填第 5 个位置，再填第 2 个位置，这称为 **arbitrary-order decoding**。

因此面试中如果问“DLM 的下一个 token 是什么”，更准确的回答是：**它预测的是所有 mask 位置的分布，然后由采样策略选择本轮提交的位置，而不是固定生成左到右的下一个 token。**

### 解码过程与采样策略

#### [Q4] DLM 每一轮会填多少个 MASK？已经填好的 token 还会变吗？

每轮填多少个 `[MASK]` 通常由 **sampling steps** 和 **mask schedule** 决定。设目标生成长度为 $L$，总采样步数为 $N$，若使用比较均匀的 schedule，平均每轮大约会新增 $L/N$ 个已确定 token。例如 $L=256, N=64$ 时，平均每轮大约固定 4 个 token。步数越少，每轮固定越多，速度更快但误差更容易累积；步数越多，每轮固定越少，质量更稳定但延迟更高。

常见的 LLaDA 类 masked DLM 会使用 **low-confidence remasking**，基本流程是：

- 对所有仍为 `[MASK]` 的位置同时预测词表分布，并给出候选 token 与置信度。
- 按置信度排序，只保留本轮计划需要的 Top-K 个高置信候选。
- 置信度较低的位置继续设为 `[MASK]`，留到下一轮重新预测。

所以它不是“随机挑位置”，也不是“置信度超过某个绝对阈值就固定”，而是**相对排序 + 数量 schedule**。比如本轮目标是让总共 40 个位置处于已确定状态，前一轮已有 30 个 token 已确定，那么本轮只需要从当前 mask 位置中额外保留置信度最高的 10 个，其余候选继续 remask。

> [!warning] “token 不变”和“隐藏状态不变”不是一回事
> 在默认 low-confidence remasking 中，已经正式提交的离散 token 通常不会再改；但由于后续其它位置会被填入新 token，双向注意力会改变全序列上下文，所以这些已提交 token 的**内部隐藏状态**仍然可能变化。

更精确地说，提交后需要区分三层状态：

- **token ID**：不再变化。
- **token embedding**：对应实际 token，因此也不再变化。
- **contextual hidden state**：仍可能变化，因为下一轮其他 `[MASK]` 会变成实际 token，已确定 token 在双向注意力中可以关注这些新 token；只要别的位置更新，$h_i^{(\ell)}$ 就可能改变。

第一层里，已确定 token 的输入 embedding 不变，所以它自己的第一层输入投影相对稳定；但它的 attention output 会因为其他位置的 $K,V$ 更新而改变。这个变化传到下一层后，第二层及以后该位置的 $Q,K,V$ 也可能随之改变。因此：==DLM 已确定 token 的离散 ID 固定，但其上下文化表示会随着全局序列逐步去噪而变化。==

#### [Q5] DLM 的并行性体现在哪里？为什么并行提交会损失质量？

DLM 的并行性主要体现在两个层面。

- **预测并行**：一次 forward 会对所有 `[MASK]` 位置同时输出 logits，而不是只看最后一个位置。
- **提交并行**：采样策略可以在一轮里同时固定多个高置信 token，从而减少总去噪轮数。

比如当前有 64 个 `[MASK]`，AR 模型通常要做 64 次 decode 才能生成 64 个 token；DLM 如果每轮提交 4 个 token，理论上 16 轮就可以完成。它用更多的单步计算换取更少的生成步数，适合利用 GPU 的并行能力。

但并行提交不是免费的。若一轮里同时确定多个 token，这些 token 在本轮无法利用彼此刚生成的信息。例如代码生成中，一个变量名、括号、缩进、类型之间可能强依赖；如果同时提交，就可能出现局部看起来置信度高、整体组合却不一致的问题。因此 DLM 的质量和速度存在明显 trade-off：**并行越强，步数越少，速度越快；但 token 间的顺序依赖建模越粗，质量风险越大。**

#### [Q6] LLaDA 如何权衡采样步数、质量和速度？

原始 LLaDA 从全 `[MASK]` 序列开始。每轮都会同时预测所有当前 mask 位置，再按置信度决定哪些预测正式保留、哪些继续保持 `[MASK]`。设生成长度为 $L$，采样步数为 $N$，$N$ 越大，每轮平均新增的 token 越少，通常约为 $L/N$，上下文逐渐完善，质量更高，但要做更多轮完整 forward；$N$ 越小，每轮同时提交更多 token，吞吐更高，但同一轮提交的 token 不能互相作为条件，推理、代码、数学等强依赖任务更容易下降。

LLaDA 常用线性 mask schedule，目标未 mask token 数随时间近似线性增加。在高质量配置中，采样步数可以接近生成长度，相当于每轮只稳定新增约一个 token，此时行为会接近顺序生成，只是每一步仍然是在完整序列上做双向预测。

**常见的权衡策略可以按并行程度来理解：**

- **纯 diffusion + low-confidence remasking**：每轮预测所有 mask 位置，保留置信度最高的候选。质量通常最好，但轮数多，推理延迟更高。
- **固定并行度 $k$**：每轮一次提交 $k$ 个 token。$k=1$ 最稳，$k$ 越大越快，但同轮提交的 token 不能相互作为条件，质量通常会下降。
- **Block diffusion / 半自回归生成**：先按左到右生成 block，block 内再使用 diffusion 并行细化。block 越大，并行度越高；block 越小，条件依赖越接近 AR。LLaDA 原论文中，Base 模型上较大 block 通常更强，而 pure diffusion 整体质量最好；Instruct 模型中 block diffusion 在 GSM8K、Math 等任务上反而更稳。
- **置信度阈值或自适应并行度**：不固定每轮提交 $k$ 个，而是只提交置信度超过阈值的位置，或者根据置信度分布动态决定本轮并行数。LLaDA 常用最大 token 概率作为置信度，Dream 类模型常用最低熵原则。近期工作还会借助辅助 AR 模型或学习式过滤器，判断哪些位置适合安全并行提交。

> [!tip] 实际调参经验
> - 数学、代码、长程依赖强的任务：更多步数、更小 block、更严格的置信度条件。
> - 开放式续写、摘要、较短回答：可以减少步数、增大 block 或一次提交更多 token。
> - 没有通用最优 schedule，通常直接在目标任务上画“准确率 vs. TPS”曲线后选 Pareto 点。

### DLM 推理与 KV Cache

#### [Q7] 为什么 DLM 不能直接使用标准 KV Cache？

自回归模型中 KV Cache 能严格成立，是因为 causal attention 保证旧 token 不会看见未来 token。对旧位置 $i\le t$，它只看 $K_{\le i},V_{\le i}$。当序列从 $[x_1,\ldots,x_t]$ 扩展到 $[x_1,\ldots,x_t,x_{t+1}]$ 时，旧位置的可见范围没有变化。新 token 在它右边，会被 causal mask 遮住，所以旧 token 的 $K,V$ 在数学上精确不变。推理时只需要计算新增 token 的 $Q,K,V$，然后让它读取历史 KV Cache。

DLM 不一样。它通常使用双向 attention，位置 $i$ 可以关注全序列 $K_{1:N},V_{1:N}$。若某一轮中第 3 个位置从 `[MASK]` 变成 `cat`，位置 3 的 value 变化可能影响所有位置的 attention 输出；这些变化再经过 FFN 和下一层 attention，会继续向后传播。理论上所有位置、所有层的隐藏状态和 $K,V$ 都可能变化，即 $K_i^{(\ell,s+1)}\ne K_i^{(\ell,s)}$ 且 $V_i^{(\ell,s+1)}\ne V_i^{(\ell,s)}$。

所以严格来说，DLM 不是不能“存” KV，而是不能像 AR 模型那样把旧 KV 当成完全正确的缓存直接复用。DLM 的缓存复用通常只能做近似：观察相邻去噪步中很多 token 的状态变化很小，于是只重算变化大的位置，稳定位置近似复用旧状态。

#### [Q8] DLM 的 decode 阶段为什么慢？复杂度瓶颈在哪里？

DLM 的 decode 慢，核心原因是每一轮去噪都要在完整序列上做 Transformer 前向。设序列长度为 $N$，采样轮数为 $T$，标准全局 attention 每轮的注意力计算约为 $O(N^2)$，总成本大致是 $O(TN^2)$。

AR 模型虽然也要生成很多步，但每步只新增一个 token，并且可以复用历史 KV Cache；decode 阶段主要计算新 token 对历史 token 的 attention。DLM 每轮会改变部分位置，双向 attention 又会让影响扩散到全序列，因此朴素实现会反复重算所有 token、所有层。

> [!tip] 面试回答可以抓住一句话
> DLM 的难点不是“不能并行”，而是**每轮并行预测之后，下一轮仍要重新理解整段序列**；双向注意力让局部 token 更新变成全局状态更新。

#### [Q9] 传统 LLaMA、无缓存 LLaMA 和原始 LLaDA 分别怎么重算？

这三个设置的重算范围可以直接对比：

- **标准 AR LLaMA，有 KV Cache**：首次 prefill 计算全部 prompt token、全部层；后续 decode 每一层只计算新增的一个 token。历史 token 的 $K,V$ 不重算，因为 causal mask 保证未来 token 不会影响过去 token 的表示。
- **标准 AR LLaMA，没有 KV Cache**：每生成一个新 token，都要重算整个 prefix 的所有 token、所有层。这只是低效基线，实际部署一般不会这么做。
- **原始 LLaDA，无缓存**：每一个 diffusion step 都会把全部 $N$ 个位置、全部 Transformer 层重算一遍。即使某些 token ID 已经固定，它们的上下文化 hidden state 仍会因为其他位置被 unmask 而变化，所以原始实现仍然重新计算整段序列。

> [!note] 一句话对比
> AR + KV Cache 的历史 token 是**数学上不变**；DLM 的已确定 token 只是**离散 ID 不变**，上下文化表示仍可能变。
