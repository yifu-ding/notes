**AI Infra的核心差异** 在于硬件感知与成本约束，核心目标是提升GPU利用率、优化显存并降低推理成本。

**Prefill与Decode阶段优化**

- Prefill预填充：计算密集型，决定首字延迟（TTFT）。
- Decode解码生成：内存带宽密集型，决定字间延迟（TBT）。
- 传统混跑会导致GPU算力与带宽互相等待，造成资源空转。

**PD分离架构设计**

- 目前工业界的主流方案是将Prefill和Decode部署在不同的GPU节点。
- Prefill池：配置大张量并行（Large TP），打满Tensor Cores算力，追求低TTFT。
- Decode池：配置小TP或单卡多路并发，榨干HBM高带宽，提升吞吐。两者通过RDMA网络异步传输KV Cache，消除计算气泡。

**MoE与KV Cache管理**

- MoE架构：通过门控网络激活少部分专家参数。面试重点在Expert Parallel的通信与计算Overlap（重叠）优化，利用Pipeline调度隐藏All-to-All通信延迟。
- KV Cache：单次推理的显存分配核心是PagedAttention的块调度与抢占机制。对于System Prompt等公共前缀共享，则采用Radix Tree（基数树）管理与LRU淘汰策略。

建议从零实现简化版推理引擎，深入理解Continuous Batching与PD分离逻辑，比单纯背概念更有竞争力。

```python
class SimpleMoE(nn.Module):
    def __init__(self, d, n_experts, top_k=2):
        super().__init__()
        self.k = top_k
        self.router = nn.Linear(d, n_experts)
        self.experts = nn.ModuleList([nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d)) for _ in range(n_experts)])

    def forward(self, x):                 # x: [T, D]
        score, idx = self.router(x).topk(self.k, dim=-1)
        weight = score.softmax(dim=-1)    # [T, K]
        output = torch.zeros_like(x)
        for k in range(self.k):
            expert_ids = indices[:, k]   
            for e, expert in enumerate(self.experts):
	            mask = expert_ids == e
                if mask.any():
	                tokens = x[mask] 
	                out = expert(tokens)
                    output[mask] += (weights[mask, k:k+1] * out)
        return output
```
