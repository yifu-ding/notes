## 蚂蚁百灵

### Ring-2.6-1T（2026 年 5 月 9 日发布，for reasoning）/ Ling-3.0-flash（2026 年 7 月 24 日发布）

1. 参数量
	- Ling-3.0-flash 参数量 124B，激活 5.1B（4.1%）
	- Ring-2.6-1T 参数量 1T，激活约 63B (6%)
2. 混合注意力
	- 5:1 交替堆叠 KDA （Kimi Delta Attention）与 MLA，train from scratch
3. **SAO** (Single-Rollout Asynchronous Optimization)
	- 每个 prompt 只有一条 rollout（不用 GRPO）
	- 用 value model (critic) 预估每条 rollout 的奖励，value model 学习的是当前 token 下的 reward 的期望
	- **如何让 critic 足够准**：1. value model 更新速度是policy（actor）的 2 倍速；2. 只训练value model 的 MoE，冻结 attn 部分；3. Skip-Observation GAE，不在 observation token (外部工具输出、报错日志等) 上逐 token 传播 advantage，防止observation 干扰 value 估计
	- 优势：长程 Agentic RL 比较必要，不然 GRPO 要 rollout 一组，耗时方差太大
4. **KPop** 解决训推不一致（高概率/低概率 token 的 clip 阈值不同，IcePop 使用同一个 ratio 阈值容易把低概率 token clip）
5. 异步调度 RL 训练 （ 和 GLM-5.2 的 slime 差不多思路）

## ByteDance

### Seedance 1.0（2025 年 6 月 11 日发布）

1. 2 个DiT，低分辨 -> 上采样 -> 高分辨 -> Decoder 
2. **时空分离** 在 Frame 内部是 Spatial Attention（文本跨模态交互），在 Frame 之间是 Temporal Attention （无文本，仅视频 token）【一个非常重要的 Infra-friendly design】
>  复杂度变化： $(THW)^2$  →   $T(HW)^2 + HW(T)^2$

3. **TSCD分段轨迹一致性蒸馏** 解决步数蒸馏后步数太少轨迹偏离、误差累积，总体 *4× 加速*
4. **师生 score distillation** 低 NFE （少步数）下采样稳定
5. **对抗式蒸馏** 学人类偏好
6. 对高分辨率 DiT 直接 RL（避免低 NFE 偏差）
7. 基础 / 运动 / 美学 Reward Models
8. 推理加速优化
	- VAE 分布式混合并行：spatial dimension + temporal dimension 
	- 后层 VAE decoder 延迟高 -> channel 减少（未公开具体宽度）→  2× VAE 解码加速
	- Kernel fusion：算子融合、中间结果不写会 HBM → 吞吐加速 15%
	- 细粒度混精（未公开混精方式）
	- 类似 AdaSpa 的 block sparse attention 思想：自适应寻找要算哪些 block（并跨 diffu step 复用）；headwise；每个 query 保留近似数量 key；text sink 保留。
	- Conv3D 的 optimized collective communication（未公开）

### Seed1.6（2025 年 6 月 25 日发布） -  统一多模态基座

1. **统一多模态基座**：230B 总参数、23B 激活的 MoE；通过图文混合持续预训练
2. 上下文从 32K 扩展至 256K

4. parallel decoding：并行 reasoning paths，探索多个解题轨迹后汇总结果

## DeepSeek

### DeepSeek V3 / V3.2（V3：2024 年 12 月；V3.2：2025 年 12 月）

1. 总参数 671B、激活 37B (5.5%)
2. auxiliary-loss-free 负载均衡（避免辅助均衡 loss 和主训练目标互相干扰）
3. **MLA（Multi-head Latent Attention，延续 V2）**。先将 KV 压缩为低维 latent。推理时投影回 Key / Value。位置部分单独保留一部分 Key。==原理是位置编码无需给所有 key，给最新的一些 key token 结果一样==。因此 KV Cache 主要存 $c_t^{KV}$ 与 $k_t^R$，存的参数量减少。
	
4. **DSA（DeepSeek Sparse Attention，V3.2 新增）**：先用轻量的 Lightning Indexer 给当前 Query $t$ 与所有历史 token $s$ 打分：

	$$I_{t,s} = \sum_{j=1}^{H_I} w^I_{t,j}\,\operatorname{ReLU}\!\left((q^I_{t,j})^\top k^I_s\right)$$

	Indexer 的 *Head 数少*、*FP8*，开销小（在 v4 进一步用 fp4）。取 top-$k$ ($k=2048$) 个 MLA latent KV 做完整 Attention。（也就是 DSA 直接在 MLA 基础上加）
5. **DSA 训练**：先保持 Dense Attention、冻结主模型，只训练 Indexer；再开启 Top-k 稀疏 Attention，Indexer 继续按独立 KL loss 训练，让稀疏选择逐步替代 Dense Attention。


### DeepSeek V4（2026 年 4 月 24 日发布）

1. 参数量
	- DeepSeek-V4-Pro：1.6T 总参数，单 Token 激活 49B 参数 （3.06%）
	- DeepSeek-V4-Flash：284B 总参数，单 Token 激活 13B 参数（4.57%）

2. 混合 Attention：CSA + HCA
	- 3 类 attention
		1. 滑动窗口：负责局部细节
		2. CSA（Compressed Sparse Attention）：保留细粒度、选择性的长程信息
			1. **合并** 沿序列维度，每 4 个 Token 压缩成一个 KV entry
			2. **稀疏** 从压缩后的历史中选择 Top-1024
		3. HCA（Heavily Compressed Attention）：提供稳定的全局压缩视野
			1. **合并** 128 个 token 合并成 1 个 kv entry
			2. 对压缩后的所有 entry 做 Dense Attention
	- 前两层使用 HCA，后续 CSA 和 HCA 交错
	- 效果：单 Token 推理 FLOPs 降至 27%，KV Cache 降至 10%
	- 训练：
		1. **Context Parallelism** ：先按原始token 压缩 kv，再按照压缩后的kv entry重新组织通信和 attn 计算【避免完整上下文在多卡并行训练的时候 all-to-all】
		2. 前 1T Token 使用 Dense Attention，达到 64K 后才引入稀疏 Attention
		3. 引入 CSA 时先单独 warm up Lightning Indexer（就是 warmup 阶段并不只算 topk，而是全算，并且用 attn 分数做 distill）。之后再联合训练，避免 Indexer 初期选错 KV 导致主模型训练不稳定。
		> 智谱 GLM-5 的 IndexShare/IndexCache 是算一次 indexer 共享给其他层。30B 模型能减少 75% 的 indexer 计算。
		
	- 推理：
		- 分层/异构 KV Cache Store 
		- KV Cache 会 offload 到 SSD，按需加载：为支持大规模共享 Prefix
3. mHC：多路残差连接（Manifold-Constrained Hyper-Connections）
	- 做法
		1. **Hyper-Connections** 标准 Transformer 只有一条 residual，Hyper-Connections 改为可以从前面任意层取 residual 加到当前层，可以多层
		2. **双随机矩阵**
			- 解决的问题是：残差混合矩阵在深层反复相乘后可能放大信号和梯度。
			- 做法：矩阵 *2 个维度方向* 都满足概率归一化。行和为 1，列和也为 1。比如下面这个矩阵：
				$$M = \begin{pmatrix} 0.4 & 0.3 & 0.2 & 0.1 \\ 0.2 & 0.4 & 0.1 & 0.3 \\ 0.3 & 0.1 & 0.4 & 0.2 \\ 0.1 & 0.2 & 0.3 & 0.4 \end{pmatrix}$$
				这样的矩阵属于 Birkhoff polytope，并满足谱范数有界，使残差映射保持 non-expansive。双随机矩阵集合对矩阵乘法封闭，因此多层堆叠后仍能维持稳定性。输入和输出映射也通过 Sigmoid 限制为非负、有界，避免不同 residual stream 相互抵消。
	- 宏观理解：给深度方向增加新的 scaling 维度
4. Hash Routing 
	- 原因：前几层 Token 表示还比较浅，Router 的语义决策可能不稳定；做法：根据 Token ID 的预定义 Hash 直接分配专家
	- 优势：避免浅层 Router 早期塌缩、分配稳定、均衡
	- 缺点：不是语义路由
5. Muon 优化器 用于预训练
	- 做法：使用 **Hybrid Newton-Schulz** 用于预训练，以提高收敛速度和训练稳定性。
		- 根据矩阵形状、数值条件选择不同迭代策略；对部分参数使用 Muon，对 embedding、norm、标量参数等继续使用 AdamW
		- 配合 Hybrid ZeRO 对 Muon optimizer state 做分片
		- 实际实现不直接做 SVD，而是使用 Newton-Schulz 迭代近似矩阵正交化
		- 对Query 和 KV entry 使用 RMSNorm，限制范数，防止过大 attn logits
	- 原理：对二维权重矩阵，AdamW 本质上对元素级梯度做自适应缩放，而 Muon 会对梯度矩阵做近似正交化：
		  $$G_{\text{muon}} \approx UV^\top, \qquad G = U\Sigma V^\top$$
	这相当于削弱不同奇异方向之间悬殊的梯度尺度，使参数在不同方向上的更新更加均衡。
6. **MegaMoE** MoE Mega-Kernel：通信、计算和访存完全流水化
	- 做法：在 router 之后，token-expert-pair 确定，然后按照 (experts, tokens) 这样的组合来细粒度划分 pipeline 的任务，Mega-Kernel 每次计算一组专家的部分 token【简单理解为分组 EP 并行（DeepGEMM） + sequence 并行，组合而成 pipeline 并行】数据布局通常是 expert-major 
	- 一个直观理解流水线，W 表示 Wave，是一组专家+部分 token
		```
		时间 1: Dispatch W0
		时间 2: Compute W0  | Dispatch W1
		时间 3: Compute W1  | Dispatch W2 | Combine W0
		时间 4: Compute W2  | Dispatch W3 | Combine W1
		时间 5: Compute W3                | Combine W2
		时间 6:                             Combine W3
		```
	- 适合 RL rollout 和 Agent Serving 中的长尾小 Batch
7. 训推一致性
	- **batch-invariant 和 deterministic Kernel** 同一 Token 在不同 Batch 组织方式下获得 bitwise 完全一致的结果
8. 上述算子使用 TileLang 开发
	- TileLang 介于 triton 和 cutlass 之间，用 tile-level DSL 描述数据流
9. 预训练：FP8 -> FP4 QAT 
	- base 模型 FP8，post-train 的 Instruct 版 FP4 + FP8 Mixed
	- MoE Expert 权重 MXFP4，其他参数 FP8，因为压缩 expert 权重收益很大
	- Query Key 和 QK 矩阵乘
		- 先 FP4（此处用于 Top-k Selector 加速约 2 倍）；QK score accumulation 是 BF16，不维护多头表示或其他，仅用于 topk 排序【此处 topk recall 为 99.7%】 
		- topk 筛选完之后会用 FP8/BF16 再算一遍 QK（也就是算两遍，但是第一遍用 4bit 计算量小，第二遍只算 top-1024，总体节省到 10%）
	- 优化器仍维护 FP32 Master Weight：权重 FP4 先 dequant 到 FP8，再和梯度算 GEMM 后累加到 FP32 的 weight 

	- **DeepSeek-V4 FP4 版本对比**

		| 模型 | FP4 类型 | 产生方式 | Expert 计算 |
		| --- | --- | --- | --- |
		| DeepSeek-V4 官方发布 | MXFP4 | Post-training QAT | 主要为 W4A8 |
		| DeepSeek-V4 NVIDIA 发布 | NVFP4 | ModelOpt PTQ | W4A4 |

10. 后训练

	- 随后使用多教师 On-Policy Distillation

	2. **理解生成解耦**、workload 分开优化
		- **Why** 
			- *理解* 主要模型结构是Vision Encoder / Video Encoder / CLIP / ViT，输出是 text、 video、image token，作为 DIT 的 condition，在这个阶段，*Token 数量少，Encoder 参数量小*，并且只需要一次 Forward，小 GEMM；
			- *生成* 主要结构是 DIT，是 denoising 过程，DIT 是大 Transformer
				1. **没有 auto regressive**，它每一次都是全量的 latent，所以 LLMs 是Decoding 阶段小 GEMM（Memory Bound），但是 Diffusion 的生成阶段是大 GEMM （compute bound）

					| Sora 类工业视频 DiT | 未公开 | 未公开 | 约 10B+ | OpenAI Sora 使用类似 DiT 的架构，具体配置未公开 |

				- 生成阶段：TP、SP 等大规模并行、 kernel fusion、FSDP 或 ZeRO
	3. **异构 workload 调度**
		- 平衡各模态的 Workload：视频编码远重于文本编码，可能不同模态各有各的 Workload；Barrier 等所有模态的 token 处理完毕之后，再去生成这个 Sample 的结果
	4. **样本间负载均衡**
		- 调度器估计每样本成本，重新调整任务分配，让每个 Rank 的负载均衡 -> 平衡总 Token 数而不是平衡样本数
		- Sequence packing 会把短样本打包到一个序列中

### Kimi K3（2026 年 7 月 16 日发布）

1. **Stable LatentMoE** 整体架构：2.8T  MoE，896 个专家，每个 Token 实际激活 16 个专家，激活比例1.8%
	1. Quantile Balancing：基于 Router 分位数做负载均衡（热门冷门专家的 token 入选阈值不同，阈值基于各自 router 分数定，让每个专家负载等于 $q$），而不是使用启发式更新规则或 balancing hyperparameter（这个辅助损失系数非常敏感）
	2. 训练时严格均衡专家负载（在路由、Dispatch 和专家执行之间建立严格平衡），适配大规模 Expert Parallel，使每个 rank 使用接近固定的输入 shape
2. **Kimi Delta Attention (KDA)**：结合线性 Attention 状态更新与局部精确 Attention，将历史 KV 压缩到固定大小的可递推矩阵 $S$ 中，支持 1M 上下文。

	> [!abstract] KDA 直观理解
	>  1. 不保存历史 KV，而是将其压缩成固定大小的关联记忆矩阵 $S_t \in \mathbb{R}^{d_k \times d_v}$，通过递推更新维护（手动反传，可证明等价性），不随着序列长度变化大小。
	> 2. $S$ 保存的是 Key→Value 的映射关系压缩，*既包含历史 KV 信息也包含映射关系*，无法再还原每一对独立的历史 KV。
	> 3. $K_t$ 决定在状态 S 的哪个方向上更新，$V_t$ 决定更新内容。

	**标准线性 Attention**

	标准线性 Attention 的更新与读取：

	$$S_t = S_{t-1} + k_t v_t^\top, \qquad o_t = S_t^\top q_t$$

	利用矩阵乘法对加法的分配律和结合律，展开后等价于：

	$$o_t = \sum_{i=1}^{t} v_i (k_i^\top q_t)$$

	所以，kv 的历史状态 S 可以通过递推更新。

	>  通用的 Softmax 的 Attention 无法这样压缩，因为 $\operatorname{softmax}(qK^\top)$ 的归一化权重依赖当前 Query，不同 Query 产生不同权重，因此无法提前将所有 KV 聚合为与 Query 无关的固定矩阵。
	>  
	>  因此，通用线性 Attention 会带特征映射 $\phi$：
	>  
	>  $$S_t = \sum_{i=1}^{t} v_i \phi(k_i)^\top, \qquad o_t = \frac{S_t \phi(q_t)}{\left(\sum_{i=1}^{t} \phi(k_i)\right)^\top \phi(q_t)}$$

	

	**KDA：遗忘门 + Delta 修正**

	KDA 在线性 Attention 基础上新增两个机制：

	$$\widetilde{S}_{t-1} = D_t S_{t-1}$$

	$$\hat{v}_t = \widetilde{S}_{t-1}^\top k_t$$

	$$S_t = \widetilde{S}_{t-1} + \beta_t\, k_t (v_t - \hat{v}_t)^\top$$

	$$o_t = S_t^\top q_t$$

	- $D_t$：遗忘门（是对角矩阵），按通道衰减旧记忆。这是 KDA 最核心的变化：每个 Key 特征维度都有独立的遗忘率。
	- $\hat{v}_t$：旧状态通过当前 $k_t$ 读出的预测 Value
	- $v_t - \hat{v}_t$：需要补写入 $S$ 的误差。
	- $k_t$：决定误差沿哪个 Key 方向写入状态
	- $\beta_t$：修正强度。*D 和 beta 都通常由当前 hidden state 经过可学习投影和 Sigmoid 得到，**可学习的**乘法式位置编码，由内容动态决定记忆衰减。*
	- $S$：每个新序列都重新全 0 初始化自己的 $S$。


	**Delta 修正的严格推导** 读出旧预测 $\hat{v}_t$ → 计算误差 $v_t - \hat{v}_t$ → 沿 $k_t$ 方向将误差写回 $S$。更新后再用同一个 $k_t$ 查询，误差被精确抵消。**直观结论：更新了 $S$ 矩阵之后，再用 $k_t$ 去查询的时候可以精确地得到 $v_t$。**

	设 $e_t = v_t - \hat{v}_t = v_t - S_{t-1} k_t$，更新后用 $k_t$ 查询：

	$$S_t k_t = \left(S_{t-1} + \beta_t\, e_t k_t^\top\right) k_t = S_{t-1} k_t + \beta_t\, e_t \|k_t\|^2 = \hat{v}_t + \beta_t \|k_t\|^2 (v_t - \hat{v}_t)$$

	若 $k_t$ 归一化（$\|k_t\|^2 = 1$）且 $\beta_t = 1$：

	$$S_t k_t = \hat{v}_t + (v_t - \hat{v}_t) = v_t \checkmark$$

	若 $\beta_t < 1$：$S_t k_t = (1 - \beta_t)\hat{v}_t + \beta_t v_t$，旧预测向 $v_t$ 部分靠近。

	**工程挑战：KDA Prefix Cache** 1. 传统 Prefix Cache 直接复用 KV Cache，而 KDA 的历史状态结构不同，**无法直接套用标准 Prefix Caching**。Kimi 为此专门实现了 KDA 专用 Prefill Cache。2. 多个 rank-1 更新合成一个 dense 矩阵运算，避免 token 串行更新 S。

3. **Attention Residuals**
	1. 沿网络深度方向做 Attention
	2. 让当前层选择性地检索不同深度的历史表示，而不是只读取上一层
	3. 浅层特征不必经过几十层残差累加后才能到达深层
	4. 感觉和 deepseek 的 residual 很像？但位置不同（attn vs hidden）
4. **Per-Head Muon**：按 Attention Head 独立优化（感觉是训练的技术）
	1. 这样的原因：不同 Attention Head 的**梯度尺度不同；功能不同；谱分布不同；收敛速度**不同
	2. 按 Head 处理可以**避免大梯度 Head 主导整体更新**，也更符合 Multi-Head Attention 的结构先验
5. Gated MLA：对 MLA 增加门控控制
6. Sigmoid Tanh Unit：新的激活控制单元。Sigmoid 控制信息通过多少； Tanh 将激活限制在有界范围内；
7. **QAT**：从 SFT 开始进行 MXFP4/MXFP8 量化感知训练
8. **原生多模态** 和 Vision-in-the-loop：生成代码→运行程序→观察截图→修改代码（k2.5 就有）
9. **长程 Agent** 训练：保留完整 Thinking History
10. **推理系统：超节点、Mooncake 和 KDA Prefix Cache**
	1. 官方建议部署在至少 64 个加速器组成的 Supernode 上，因为 896 个专家需要较大的高带宽通信域
	2. 大规模 Expert Parallel；
	3. 高带宽域内 All-to-All；
	4. KDA 专用 Prefill Cache；
	5. Mooncake 分离式推理架构；
	6. 编码工作负载中超过 90% 的 Prefix Cache 命中率。
11. Kimi k1.5、Kimi k2: Online Policy Mirror Descent （同 prompt 多 rollout 和组内相对奖励，一种类似 GRPO 的 RL）

3. 原生多模态，多轮验证+推理
4. 256K 上下文，滑动窗口与全局注意力3:1混合，96 query heads，head-wise gated attention

6. EP负载均衡
	1. EP-group balancing loss：不同 EP rank 的总负载均衡
7. MIS-PO：异步、off-policy RL
	1. 同时进行 token-level 和 seq-level 的过滤
	2. 领域专家模型再自蒸馏，类似 dsv4
	3. Muon：BF6 Polar Express 偶尔出现极端中间值 -> FP16 
8. **Step-3：MFA + AFD（Attention-FFN Disaggregation）**
	- **MFA（Multi-Matrix Factorization Attention）**：在 QK 路径做多矩阵低秩分解，以更小的 latent 表示构造注意力；相比直接存每个 Head 的完整 KV，可同时降低 KV Cache 和 Attention 计算，但保留较高的注意力表达能力。
	- **AFD（Attention-FFN 分离）**：将 Attention（长上下文、偏带宽 / Cache）与 MoE FFN（大 GEMM、偏计算）的推理解耦，分别调度到适配的 GPU 集群，再通过通信流水衔接，减少同一集群内两类 workload 互相等待。
	- **模型—系统协同**：MFA 降低单 Token 的 Cache / Attention 成本，AFD 提高集群利用率；上下文越长，解码成本优势越明显。

**slime：异步 RL Infra**

1. 引擎：Megatron-LM 用于训练；SGLang 用于 rollout 
2. 调度：
	1. SGLang Router 用于分发 rollout 到不同 worker 上，负载均衡
	2. Data Buffer：用于管理 rollout 生产、trainer 消费的数据队列。
3. 训推参数同步：Megatron 更新参数后需要同步给 SGLang worker
	- 记录 staleness 和 rollout policy 的 log-prob 
4. 两种部署方式：Colocated （训推在一组机器），Disaggregated （训推独立 GPU 池）

6. 难点：旧 Policy 生成的轨迹可能与当前 Policy 不一致，即 policy staleness
